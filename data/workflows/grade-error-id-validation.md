# 判题回复编号前置：本地验收

- 需求：每道题在六段判题解析之前显示真实、完整的 32 位十六进制 error_id。
- 边界：编号仅来自服务端回执；新题未入本、正确题不入本、复习归属未匹配时明确显示无编号或待确认。不得用 candidate_id、question_id、PDF 编号或截断编号替代。
- 实现：复用现有判题、确认、题库复核返回值；补充复核结果中的 error_id，统一工具文本编号行，同步三份 Harness 提示配置。不改变判题、入本、复习、账号归属逻辑。
- 验证：`python -X utf8 -B -m unittest discover -s tests -p "test_*.py"`，283 项通过。覆盖普通入本、重复入本、复习完成、正确未入本、未关联、空编号、短编号和印刷编号；接口测试核对复核返回编号与实际入本编号一致。
- 本地加载：已重启 Web/Harness，运行预设与仓库预设 SHA-256 一致；8000 的 healthz/login、3080 首页均返回 200。
- 不调用外部模型、不修改用户题目数据。未进行真实模型新判题，也未执行外部审查或生产部署。
