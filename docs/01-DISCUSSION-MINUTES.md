# Web 版讨论纪要

> 文档版本：v0.4.0
> 确认日期：2026-08-23
> 状态：已确认
> 适用范围：李兆霖数学错题本 Web MVP

## 1. 当前结论

MVP 采用单一用户模型，但账号入口从旧版单页自动注册/登录改为两个明确流程：已有账号使用手机号验证码登录，新用户使用手机号、验证码和密码注册并确认协议；注册成功自动登录并进入个人错题本。产品不建立任何前台身份、组织或资料完善流程。

## 2. 已确认决策

### DEC-001 开放手机号注册

- 所有用户可使用中国大陆手机号注册，已有账号使用短信验证码登录。
- v0.3.3 的同一入口已被 v0.4.0 的独立登录页和注册页替代。
- 登录未注册号码和注册已存在号码提供明确跳转反馈；该产品选择带来账号枚举风险，必须通过独立安全复核、限流、CAPTCHA和审计告警后才能上线。

### DEC-002 注册后直接使用

- 新用户在注册页完成手机号验证、密码设置和协议确认后，原子创建账号、凭据和会话，并直接进入工作台。
- 不要求填写姓名、昵称、年级、年龄、身份或学习偏好。
- 新账号立即拥有一个空错题本。

### DEC-003 只有一种普通用户

- 不区分学生、家长、监护人、教师、家庭所有者或其他前台角色。
- 不提供身份选择或角色切换。
- 所有普通用户具有相同的个人错题本功能。

### DEC-004 一账号一私有错题本

- 所有原图、作答、错题、推荐、复习、PDF 和导出直接归属 user_id。
- 服务端会话解析 user_id，客户端不能选择或覆盖数据作用域。
- 用户内容默认不跨账号复用。

### DEC-005 暂不做家庭和学生档案

- MVP 不建设家庭、家庭所有者、家庭成员、家庭邀请码或学生档案。
- 不提供成员管理、代管、共享、协作或账号间数据转移。
- 历史的 TENANT-001、TENANT-002、AUTHZ-001 和 STUDENT-001 保留编号但移出 MVP。

### DEC-006 暂不做身份与监护认证

- 不询问年龄或未成年人状态。
- 不做监护人绑定或监护同意门。
- 不采集身份证、人脸、真实姓名或法定监护关系证明。
- 手机号验证只证明当前用户控制该号码，不表示实名或法定身份已经核实。
- 历史的 AUTH-003 保留编号但移出 MVP。

### DEC-007 候选与正式结果分离

- OCR、切分、判题、错因和推荐先作为候选。
- 用户确认和确定性质量门之后才能写正式错题或题库。
- 输入变化必须创建新版本并使旧分析失效。

### DEC-008 推荐只使用已验证题

- 推荐必须同时满足验证、来源授权、难度、知识点和去重要求。
- 合格题不足时展示缺口，不以低质量题补足数量。

### DEC-009 任务失败可恢复

- 解析、判题、推荐、导出和 PDF 使用检查点。
- 用户可以看到当前状态、数据是否保存和下一步。
- 刷新、重复提交和 Worker 重启不得生成重复正式记录或重复扣费。

### DEC-010 云部署继续后置

- 当前只建设和验收本地生产等价环境。
- 本地完整学习闭环、安全复核和恢复演练通过后，才能由用户人工批准云部署。

### DEC-011 继续使用 Python Web 服务并治理已知风险

- 当前继续使用 Python + ASGI，不因语言偏好重写为 Java、Go 或 Rust。
- Python 适合当前以数据库、文件和外部服务调用为主的模块化单体；是否拆分或更换语言必须以容量、延迟、成本和故障数据为依据。
- 当前首要风险不是 Python 本身，而是异步 ASGI 请求路径中仍直接执行同步 MySQL、文件和 PDF 操作。这些操作会占用事件循环，放大并发请求的排队时间。
- OCR、判题和 PDF 等耗时或 CPU 密集任务应移出 Web 请求进程，交给有并发上限、超时、幂等和失败恢复能力的 Worker。
- 上传链路不能长期依赖把整个请求体读入内存；生产目标为流式写入对象存储，并同时设置请求大小、并发数和处理时限。
- MySQL 访问应建立有上限的连接池和明确的连接、查询、事务超时，避免每次操作新建连接以及数据库故障拖垮 Web 进程。
- Web 服务应支持多进程运行，并设置 CPU、内存、请求时限和优雅退出边界；本地文件存储只用于本地模拟，生产使用 OSS。
- Python 依赖需要固定兼容范围、生成可复现依赖清单并持续扫描漏洞；运行时输入和接口继续通过确定性 Schema、测试和契约校验。
- GIL 对当前数据库型 API 不是主要风险；只有压测证明 CPU 成为瓶颈后，才考虑进程扩容、局部原生实现或语言拆分。
- 处置顺序固定为：耗时任务移入 Worker → 上传流式化/OSS → MySQL 连接池与超时 → 多 Web 进程及资源限制 → 依赖锁定与扫描 → 压测和故障演练。

### DEC-012 登录与注册拆分

- 登录页只服务已有账号，使用手机号和6位验证码。
- 注册页只服务新账号，使用手机号、6位验证码、6—20位密码和协议确认。
- 登录页进入注册页时回填合法手机号；注册页返回登录页时清空注册表单。
- 验证码填满后只激活按钮，不自动提交。
- 注册成功自动登录；仍无昵称、年级、身份、家庭、监护或实名步骤。
- 单手机号短信上限调整为5次/小时、10次/滚动24小时；验证码5分钟有效、60秒冷却、错误5次作废。
- 目标细节以 `13-LOGIN-REGISTER-PRD.md` 为准；v0.4.0 本地候选已完成场景拆分、密码/协议记录和 OpenAPI 对齐。v0.3.3 单入口仅保留为历史迁移语境，不能作为当前完成证据。

## 3. MVP 包含

- 独立手机号注册、验证码登录、退出和会话撤销；
- 注册密码安全存储、用户协议与隐私政策版本确认；
- 防验证码轰炸、CAPTCHA、预算熔断和稳定错误响应；
- 注册成功后直接进入个人错题本；
- 单题、作答和整卷采集，以及手工录入；
- 切分、确认、判题、首错步骤和错因；
- 正式错题本、推荐、复习和 PDF；
- 任务恢复、导出、注销和最小运营复核；
- user_id 隔离和私有内容保护。

## 4. MVP 暂不包含

- 姓名、昵称、年级、年龄或身份资料；
- 家庭、成员、学生档案、邀请码和角色；
- 监护人绑定或监护同意；
- 实名、身份证、人脸或法定关系核验；
- 教师协作、用户共享和公开社区；
- 海外手机号、用户名登录、密码登录和第三方社交登录；
- 模型自动写正式数据库或批准部署。

## 5. 统一业务口径

| 主题 | 口径 |
|---|---|
| 注册与登录 | 独立页面和独立挑战场景；登录用验证码，注册用验证码和密码 |
| 首次进入 | 注册成功自动登录并直接进入空错题本 |
| 账号主体 | 一种普通用户，不采集身份和资料 |
| 数据归属 | 全部个人学习数据归属服务端会话 user_id |
| 用户内容 | 默认私有，不跨账号复用 |
| 错题入本 | 题干、作答和判题先确认 |
| 推荐 | 只使用已验证且授权允许的题 |
| 任务恢复 | 从最近检查点继续，输入变化创建新任务 |
| 导出 | 只导出当前 user_id 的数据 |
| 注销 | 二次手机号验证后执行并撤销全部会话 |

## 6. 风险与处理

| 风险 | 处理原则 |
|---|---|
| 短信轰炸 | 多维限流、挑战、预算和熔断 |
| 账号枚举 | 产品要求明确账号存在性跳转；以多维限流、CAPTCHA、审计告警和独立安全复核控制风险 |
| 跨用户越权 | 所有查询、对象键和任务均以会话 user_id 校验 |
| 候选误写正式库 | 输入版本、Schema、置信度和幂等质量门 |
| 私有题跨用户泄露 | 用户授权内容默认仅当前 user_id 使用 |
| 模型不确定 | waiting_confirmation 或人工复核，不猜测 |
| 早期代码曾有监护/租户逻辑 | 已通过前向迁移和 user_id 领域边界移出产品入口；后续变更仍须先形成迁移与回滚方案 |
| ASGI 路径执行同步数据库、文件或 PDF 操作 | 移入受控 Worker 或有界线程；用并发压测验证事件循环不被阻塞 |
| 上传请求体整体驻留内存 | 流式写入 OSS，并限制大小、并发和处理时间 |
| MySQL 每次操作新建连接或无明确超时 | 使用有上限的连接池，配置连接、查询和事务超时 |
| CPU 密集任务挤占 Web 进程 | Worker 隔离并设置资源上限；只有测量后才考虑语言拆分 |
| Python 第三方依赖风险 | 固定依赖、生成可复现清单、漏洞扫描和升级回归 |
| 单进程或单机文件状态 | 多 Web 进程、优雅退出；生产文件统一存入 OSS |
