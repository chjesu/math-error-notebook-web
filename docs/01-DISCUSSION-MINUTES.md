# Web 版讨论纪要

> 文档版本：v0.3.2
> 确认日期：2026-08-22
> 状态：已确认
> 适用范围：李兆霖数学错题本 Web MVP

## 1. 当前结论

MVP 采用单一用户模型：所有用户使用手机号验证码注册或登录，成功后直接进入自己的个人错题本。产品不建立任何前台身份、组织或资料完善流程。

## 2. 已确认决策

### DEC-001 开放手机号注册

- 所有用户可使用中国大陆手机号和短信验证码注册或登录。
- 同一入口兼容首次注册与已有账号登录。
- 发送和验证响应不能泄露手机号是否已注册。

### DEC-002 注册后直接使用

- 手机号验证成功后原子创建账号和会话，并直接进入工作台。
- 不要求填写姓名、昵称、年级、年龄、身份或学习偏好。
- 新账号立即拥有一个空错题本。

### DEC-003 只有一种普通用户

- 不区分学生、家长、监护人、教师、家庭所有者或其他前台角色。
- 不提供身份选择或角色切换。
- 所有普通用户具有相同的个人错题本功能。

### DEC-004 一账号一私有错题本

- 所有原图、作答、错题、推荐、复习、PDF 和导出直接归属 user_id。
- 服务端会话解析 user_id，客户端不能选择或覆盖数据作用域。
- 用户内容默认不跨账号复用。

### DEC-005 暂不做家庭和学生档案

- MVP 不建设家庭、家庭所有者、家庭成员、家庭邀请码或学生档案。
- 不提供成员管理、代管、共享、协作或账号间数据转移。
- 历史的 TENANT-001、TENANT-002、AUTHZ-001 和 STUDENT-001 保留编号但移出 MVP。

### DEC-006 暂不做身份与监护认证

- 不询问年龄或未成年人状态。
- 不做监护人绑定或监护同意门。
- 不采集身份证、人脸、真实姓名或法定监护关系证明。
- 手机号验证只证明当前用户控制该号码，不表示实名或法定身份已经核实。
- 历史的 AUTH-003 保留编号但移出 MVP。

### DEC-007 候选与正式结果分离

- OCR、切分、判题、错因和推荐先作为候选。
- 用户确认和确定性质量门之后才能写正式错题或题库。
- 输入变化必须创建新版本并使旧分析失效。

### DEC-008 推荐只使用已验证题

- 推荐必须同时满足验证、来源授权、难度、知识点和去重要求。
- 合格题不足时展示缺口，不以低质量题补足数量。

### DEC-009 任务失败可恢复

- 解析、判题、推荐、导出和 PDF 使用检查点。
- 用户可以看到当前状态、数据是否保存和下一步。
- 刷新、重复提交和 Worker 重启不得生成重复正式记录或重复扣费。

### DEC-010 云部署继续后置

- 当前只建设和验收本地生产等价环境。
- 本地完整学习闭环、安全复核和恢复演练通过后，才能由用户人工批准云部署。

## 3. MVP 包含

- 手机号验证码注册、登录、退出和会话撤销；
- 防验证码轰炸、CAPTCHA、预算熔断和统一响应；
- 注册成功后直接进入个人错题本；
- 单题、作答和整卷采集，以及手工录入；
- 切分、确认、判题、首错步骤和错因；
- 正式错题本、推荐、复习和 PDF；
- 任务恢复、导出、注销和最小运营复核；
- user_id 隔离和私有内容保护。

## 4. MVP 暂不包含

- 姓名、昵称、年级、年龄或身份资料；
- 家庭、成员、学生档案、邀请码和角色；
- 监护人绑定或监护同意；
- 实名、身份证、人脸或法定关系核验；
- 教师协作、用户共享和公开社区；
- 海外手机号、用户名密码和第三方社交登录；
- 模型自动写正式数据库或批准部署。

## 5. 统一业务口径

| 主题 | 口径 |
|---|---|
| 注册与登录 | 同一手机号验证码流程 |
| 首次进入 | 验证成功后直接进入空错题本 |
| 账号主体 | 一种普通用户，不采集身份和资料 |
| 数据归属 | 全部个人学习数据归属服务端会话 user_id |
| 用户内容 | 默认私有，不跨账号复用 |
| 错题入本 | 题干、作答和判题先确认 |
| 推荐 | 只使用已验证且授权允许的题 |
| 任务恢复 | 从最近检查点继续，输入变化创建新任务 |
| 导出 | 只导出当前 user_id 的数据 |
| 注销 | 二次手机号验证后执行并撤销全部会话 |

## 6. 风险与处理

| 风险 | 处理原则 |
|---|---|
| 短信轰炸 | 多维限流、挑战、预算和熔断 |
| 账号枚举 | 已注册和未注册保持等价响应 |
| 跨用户越权 | 所有查询、对象键和任务均以会话 user_id 校验 |
| 候选误写正式库 | 输入版本、Schema、置信度和幂等质量门 |
| 私有题跨用户泄露 | 用户授权内容默认仅当前 user_id 使用 |
| 模型不确定 | waiting_confirmation 或人工复核，不猜测 |
| 当前代码仍有监护/租户逻辑 | 架构步骤先形成迁移方案，再修改状态机和 Schema |

## 7. 后续批准项

以下不阻止本地开发，但阻止生产部署：

| 项目 | 负责人 | 退出条件 |
|---|---|---|
| 短信模板、预算、固定出口和故障流程 | SEC + SRE | 小流量验证、熔断和回滚 |
| 手机号保护与密钥托管 | SEC + DATA | 威胁审查和密钥权限演练 |
| 导出格式和下载期限 | PO + SEC | 越权、过期和可读性验收 |
| 注销与数据保留 | PO + DATA + SEC | 数据分类表和删除证明 |
| 复习阶段和掌握规则 | PO + MATH | 固定样本回归 |

## 8. 被替代决策

v0.2.0—v0.3.1 中关于家庭租户、学生档案、角色、监护同意和资料完善的产品决策，从 v0.3.2 起全部移出 MVP。历史版本仍保留在 Git 中供追溯，不能继续作为当前实现验收口径。
