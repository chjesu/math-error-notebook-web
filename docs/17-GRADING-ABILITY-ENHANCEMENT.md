# 判题能力增强设计与验收基线

## 1. 目标

在不绕过用户确认门、不开放 Shell/MCP、不让模型直接写库的前提下，提高题目判定的准确率、可复核性与同图多题连续性。

## 2. 判题流水线

1. 服务端从 `attempt.intake_id` 回查用户拥有的上传文件，生成去 EXIF、有大小上限的模型预览图。
2. 独立解题阶段只接收确认后的完整题干和原始图片，不接收学生作答；输出参考解法、最终答案、置信度和最多 8 个受限验算表达式。
3. 服务端使用 AST 白名单计算器验证模型声明的等式；只允许数字、有限变量、四则运算、有限次幂和 `sqrt`，禁止属性、导入、文件、网络、进程和任意函数调用。
4. 复核判题阶段在该图片已有的父 Harness 线程中执行，同时接收原图、学生作答、独立解题结果和确定性验算报告，输出最终判题候选。
5. 仍由服务端校验资源 ID、输入版本、Schema 和置信度；候选只有经过用户确认接口才可入本。

## 3. 父线程规则

- 同一上传文件拆出的题目共享首题建立的 Harness 线程。
- 服务端按 `file_id` 查找同组题目中已有的线程映射；浏览器看不到 thread id。
- 子题继续对话、判题和上下文压缩时复用该父线程；不为同一 thread id 建立重复数据库映射。

## 4. 动态模型路由

| 难度 | 确定性触发条件 | 独立解题 | 复核判题 |
|---|---|---|---|
| 常规 | 未命中下列条件 | Terra / medium | Sol / high |
| 困难 | 图形依赖、解析几何、函数综合、数列综合等 | Sol / xhigh | Sol / xhigh |
| 极难 | 证明题、空间几何或多步骤压轴特征 | Sol / max | Sol / max |

动态升级只改变本题的模型路由，不改变认证、写库或确认权限。

## 5. 失败策略

- 原图不存在、解题失败、验算冲突或复核失败时，接口返回安全失败，不生成或提交候选。
- 网络错误沿用 Codex 路由器已有的有界重试与脱敏审计；认证、证书和非网络错误不盲目重试。
- 受限验算不支持的表达式标记为 `unsupported`，不能伪装成已验证。

## 6. 验收标准

- 判题调用同时收到题目原图。
- 同图第二题的判题、追问和压缩复用首题线程。
- 独立解题输入中没有 `answer_text`，复核输入包含独立解题及验算报告。
- 白名单计算器拒绝属性访问、未知函数、超长表达式、过大指数和非白名单变量。
- 常规题、困难题、极难题分别命中 medium/high、xhigh、max 路由。
- 全量单元测试通过，且本地完整流程不绕过现有确认和提交门。
