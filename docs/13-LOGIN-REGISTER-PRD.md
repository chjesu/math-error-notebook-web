# 手机验证码登录与注册产品设计

> 文档版本：v0.4.0  
> 状态：已确认，待实现  
> 适用端：响应式 Web/H5；小程序和 App 复用业务规则，控件按平台规范实现  
> 来源：用户提供的 `login_register_prd.md`，经项目边界、安全约束和现有错题本流程补齐

## 1. 产品决策

v0.4.0 将旧版“一个验证码入口自动判断注册或登录”改为两个明确页面：

- 已有账号从“验证码登录”进入；
- 新用户从“手机号注册”进入，提交手机号、验证码和密码；
- 注册成功后自动建立会话并进入个人错题本；
- 登录页与注册页可相互跳转；
- 仍不采集姓名、昵称、年级、年龄、身份、家庭、学生档案、监护或实名信息。

本期登录方式仍为手机验证码。注册时设置的密码作为账号凭据保存，但本期不提供密码登录入口；在密码登录或密码找回产品需求获批前，前端不得展示未实现入口。

## 2. 页面与路由

| 页面 | 建议路由 | 主要用途 |
|---|---|---|
| 验证码登录 | `/login` | 已注册手机号获取验证码并登录 |
| 手机号注册 | `/register` | 新手机号验证、设置密码并创建账号 |
| 用户协议 | `/legal/terms` | 展示当前生效协议，支持返回原表单 |
| 隐私政策 | `/legal/privacy` | 展示当前生效政策，支持返回原表单 |
| 工作台 | `/` | 登录或注册成功后的唯一业务落点 |

登录页点击“没有账号？立即注册”时，将合法手机号作为页面内导航状态带到注册页并回填；不得把手机号放入 URL 查询参数、日志或埋点。注册页点击“已有账号？去登录”时按原始 PRD 清空注册表单，不携带验证码或密码。

## 3. 公共输入标准

### 3.1 手机号

| 状态 | 触发条件 | UI 表现 | 文案 |
|---|---|---|---|
| 初始 | 页面加载 | 正常边框，占位符“请输入 11 位手机号” | 无 |
| 输入中 | 用户键入 | 只接受数字，最多11位；粘贴时过滤空格和常见分隔符 | 无 |
| 失焦失败 | 不满足中国大陆手机号格式 | 红色边框，错误紧邻字段 | 手机号格式不正确 |
| 校验通过 | 11位合法手机号 | 清除字段错误 | 无 |

前端校验只改善体验，服务端仍必须独立规范化和验证。手机号变化后，已有验证码、挑战令牌和倒计时立即失效，避免用 A 号码的验证码提交 B 号码。

### 3.2 验证码

验证码固定为6位数字：

- 初始占位符为“请输入 6 位验证码”；
- 只接受数字，支持粘贴完整6位验证码；
- 1—5位为未完成状态，6位时只激活提交按钮，不自动提交；
- 验证失败后保留手机号，用户再次输入时立即清除验证码字段错误；
- 获取新验证码后清空旧验证码输入。

不采用“填满后自动登录”，避免用户尚未完成协议确认或误粘贴时触发敏感操作。

### 3.3 协议确认

登录和注册提交前均要求用户主动勾选：

> 我已阅读并同意《用户协议》和《隐私政策》

协议名称可点击打开完整正文，返回后保留除密码可见状态之外的表单内容。服务端记录协议版本、确认时间和内部用户/会话标识，不记录页面截图或无关身份信息。未勾选时提交按钮禁用；键盘或辅助技术触发提交时服务端仍返回 `agreement_required`。

## 4. 验证码登录页

### 4.1 页面元素

- 李兆霖数学错题本现有 Logo 和产品名称；
- 手机号输入框；
- 验证码输入框；
- 获取验证码按钮；
- 协议复选框及协议入口；
- 登录按钮；
- “没有账号？立即注册”链接；
- 服务端要求时出现的 CAPTCHA。

### 4.2 获取验证码按钮

| 状态 | 条件 | 文字/表现 | 可用性 |
|---|---|---|---|
| 禁用 | 手机号为空或格式错误 | 获取验证码 | 不可点击 |
| 就绪 | 手机号合法 | 获取验证码 | 可点击 |
| 请求中 | 请求未完成 | 转圈并保持按钮宽度 | 不可点击 |
| 倒计时 | 服务端确认已受理 | `XXs 后重试` | 不可点击 |
| 可重发 | 倒计时归零 | 重新发送 | 可点击 |
| CAPTCHA | 服务端要求人机验证 | 显示验证控件 | 完成后重新请求 |

前端倒计时不是事实源。刷新、切换页面或修改系统时间不能绕过服务端冷却。供应商结果未知时不得直接进入可重发状态，也不得自动重发。

### 4.3 登录按钮

| 状态 | 条件 | 表现 |
|---|---|---|
| 禁用 | 手机号、6位验证码或协议确认任一不完整 | 置灰，不可提交 |
| 就绪 | 三项均有效 | 主按钮点亮 |
| 提交中 | 用户点击登录 | “登录中”及 loading，禁止重复提交 |

### 4.4 登录结果

成功后关闭 loading，显示短暂“登录成功”，以服务端会话替换当前页面并进入工作台。

| 场景 | 稳定错误码 | 用户文案 | 表单处理 |
|---|---|---|---|
| 验证码错误 | `invalid_code` | 验证码不正确，请重新输入 | 保留手机号，清空验证码 |
| 验证码过期 | `code_expired` | 验证码已失效，请重新获取 | 保留手机号，清空验证码和挑战 |
| 错误达到5次 | `too_many_attempts` | 验证次数过多，请重新获取验证码 | 保留手机号，清空验证码和挑战 |
| 手机号未注册 | `phone_not_registered` | 该手机号尚未注册，请前往注册 | 保留手机号，提供注册链接 |
| 请求频繁 | `rate_limited` | 操作过于频繁，请稍后重试 | 保留输入，按服务端时间等待 |
| 网络失败 | `network_error` | 网络异常，请检查网络后重试 | 保留输入，允许人工重试 |
| 服务暂不可用 | `temporarily_unavailable` | 服务暂时不可用，请稍后重试 | 保留手机号，不自动重发 |

## 5. 手机号注册页

### 5.1 页面元素

- 李兆霖数学错题本现有 Logo 和产品名称；
- 手机号输入框；
- 验证码输入框；
- 获取验证码按钮；
- 密码输入框及显示/隐藏按钮；
- 协议复选框及协议入口；
- 注册按钮；
- “已有账号？去登录”链接；
- 服务端要求时出现的 CAPTCHA。

### 5.2 已注册手机号

注册场景请求验证码时可以返回 `phone_already_registered`。页面使用对话框说明“该手机号已注册账号，是否前往登录”，确认后进入登录页并回填手机号，取消则停留注册页。

该明确反馈会提高账号枚举风险。上线前必须通过独立安全复核，至少采用统一限流、CAPTCHA升级、响应字段最小化、审计告警和禁止批量查询；不得在日志、客服检索或分析事件中进一步暴露手机号状态。

### 5.3 密码

| 状态 | 条件 | 文案 |
|---|---|---|
| 初始 | 页面加载 | 占位符“请设置登录密码” |
| 太短 | 少于6个字符 | 密码长度不能小于 6 位 |
| 太长 | 超过20个字符 | 密码长度不能超过 20 位 |
| 通过 | 6—20个允许字符 | 清除错误 |

补充规则：

- 允许字母、数字和常见可打印特殊符号；禁止空格控制字符；
- 默认隐藏，眼睛按钮只改变当前显示，不写入日志或持久化；
- 本期不启用“必须同时含字母和数字”的可选强度门，避免与原稿的可选规则冲突；
- 不设置二次确认框，用户可通过显示按钮检查输入；
- 前端不得保存密码；服务端只保存经批准的自适应密码哈希和独立盐，原文不得进入数据库、日志、审计或模型输入；
- 密码哈希参数、pepper、迁移和轮换方案必须经过安全复核后实施。

### 5.4 注册按钮

| 状态 | 条件 | 表现 |
|---|---|---|
| 禁用 | 手机号、6位验证码、合法密码或协议确认任一不完整 | 置灰，不可提交 |
| 就绪 | 所有字段有效 | 主按钮点亮 |
| 提交中 | 用户点击注册 | “注册中”及 loading，禁止重复提交 |

### 5.5 注册结果

注册成功必须在一个事务内完成验证码消费、唯一账号创建、密码凭据保存、协议版本记录和会话创建；随后显示“注册成功”并自动进入工作台。

| 场景 | 稳定错误码 | 用户文案 | 表单处理 |
|---|---|---|---|
| 验证码错误 | `invalid_code` | 验证码不正确，请重新输入 | 保留手机号和密码，清空验证码 |
| 验证码过期 | `code_expired` | 验证码已失效，请重新获取 | 保留手机号和密码，清空验证码和挑战 |
| 手机号已注册 | `phone_already_registered` | 该手机号已注册，请直接登录 | 不提交密码，提供登录入口 |
| 密码不合规 | `weak_password` | 请设置 6—20 位密码 | 聚焦密码字段 |
| 未同意协议 | `agreement_required` | 请先阅读并同意用户协议和隐私政策 | 聚焦协议复选框 |
| 网络失败 | `network_error` | 网络异常，请检查网络后重试 | 保留输入，允许人工重试 |

重复提交同一有效注册请求只能创建一个账号和一个当前提交对应的会话结果；手机号唯一约束是最终事实源。

## 6. 后端状态标准

### 6.1 验证码挑战

每个挑战必须带 `purpose=login|register`，两种场景不得混用验证码或挑战令牌。

```text
pending → sent → verified
   │        ├→ expired
   │        ├→ locked
   │        └→ cancelled
   ├→ delivery_failed
   └→ cancelled
```

| 状态 | 含义 | 是否可验证 |
|---|---|---:|
| `pending` | 已创建，正在等待供应商结果 | 否 |
| `sent` | 供应商已受理 | 是 |
| `verified` | 已成功消费 | 否 |
| `cancelled` | 被同手机号同场景的新挑战替代 | 否 |
| `expired` | 超过5分钟 | 否 |
| `locked` | 错误达到5次 | 否 |
| `delivery_failed` | 未可靠受理 | 否 |

登录挑战成功时只能为已存在且 `active` 的账号创建会话；注册挑战成功时只能创建尚不存在的手机号账号。挑战、手机号和业务场景必须同时匹配。

### 6.2 账号与会话

账号沿用 `active`、`locked`、`pending_delete`、`deleted`。只有 `active` 可以登录。注册成功不增加资料完善状态；会话仍采用服务端安全 Cookie，支持当前退出和全端退出。

## 7. 风控与业务规则

| 规则 | 标准 |
|---|---:|
| 验证码有效期 | 5分钟 |
| 发送冷却 | 60秒，前后端同时执行 |
| 单手机号 | 5次/小时、10次/滚动24小时 |
| 验证错误 | 同一挑战5次后作废 |
| IP、IP前缀、设备、场景、平台 | 保留现有多维硬限流与预算熔断 |
| CAPTCHA | 达风险阈值时服务端要求；通过后仍不能绕过硬限流 |
| 供应商未知结果 | 不自动重发 |

登录与注册分别计业务场景，但手机号和平台总预算必须合并计数，避免在两个页面之间切换绕过成本上限。

## 8. 目标 API

v0.4.0 目标契约：

| 方法与路径 | 用途 |
|---|---|
| `POST /v1/auth/login/otp/request` | 已注册账号申请登录验证码 |
| `POST /v1/auth/login/otp/verify` | 校验验证码并建立登录会话 |
| `POST /v1/auth/register/otp/request` | 新账号申请注册验证码 |
| `POST /v1/auth/register/complete` | 校验验证码、设置密码、确认协议、创建账号和会话 |
| `GET /v1/session` | 查询当前会话 |
| `DELETE /v1/session` | 退出当前会话 |
| `DELETE /v1/sessions` | 全端退出 |

登录验证请求只接受：`phone`、`challenge_token`、`code`、`terms_version`、`privacy_version`。注册完成请求只接受：`phone`、`challenge_token`、`code`、`password`、`terms_version`、`privacy_version`。不得接受昵称、年级、身份、家庭、监护或可改变数据归属的 `user_id`。

当前 `openapi/web-v1.json` 和代码仍是 v0.3.3 单入口实现。在认证重构完成、测试通过并迁移后，才能升级机器契约；本文件不宣称目标 API 已实现。

## 9. 埋点与隐私

允许事件：页面打开、手机号格式校验结果、验证码请求结果分类、CAPTCHA展示、提交结果分类、登录/注册成功和页面跳转。事件只记录场景、内部伪标识、错误码、耗时和版本：

- 不记录完整手机号、验证码、密码、挑战令牌、Cookie或CAPTCHA token；
- 不在URL中携带手机号；
- 不记录输入框原文和供应商请求体；
- 不将认证数据发送给模型。

## 10. 验收标准

1. 登录和注册为两个页面，互相跳转符合手机号回填/清空规则。
2. 所有字段、按钮、loading、倒计时、CAPTCHA和错误态均符合本文件状态表。
3. 登录场景不会为未注册手机号创建账号；注册场景不会覆盖已有账号。
4. 注册成功原子创建账号、密码凭据、协议记录和会话，并直接进入工作台。
5. 验证码跨手机号、跨场景、过期、重放、并发消费和第5次错误均被拒绝。
6. 60秒冷却、5次/小时、10次/日及原有IP/设备/平台限制不可由刷新、换页面或并发绕过。
7. 密码和认证秘密不进入日志、错误、审计、分析、仓库或模型输入。
8. 已注册/未注册明确反馈经过独立安全评审和批量枚举攻击测试；未通过不得生产上线。
9. 键盘、屏幕阅读器、移动端软键盘和粘贴验证码均可完成流程。
10. 当前实现差距、迁移、回滚和灰度证据齐全后，才能把认证模块标记为 v0.4.0 完成。

## 11. 当前实现差距

当前代码仍采用单一 `/v1/auth/otp/request`、`/v1/auth/otp/verify`：正确验证码会对新手机号自动建号，对旧手机号登录，且没有密码和协议记录。因此以下均为待开发：

- 登录/注册场景拆分及挑战用途隔离；
- 独立登录页、注册页和跳转状态；
- 注册密码安全存储；
- 协议版本确认记录；
- `phone_not_registered`、`phone_already_registered` 等目标错误；
- 10次/日的新手机号短信上限；
- 新目标 API、迁移、回滚、E2E与安全复核。
