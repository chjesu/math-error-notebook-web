## v0.3.1 产品基线

1. 用户可以使用中国大陆手机号和短信验证码注册、登录；系统必须具备防验证码轰炸能力。
2. 注册流程不得因“开放注册”被排除在 MVP 之外。
3. 成年人注册后可以创建或受邀加入家庭；学生只能通过监护邀请和档案绑定加入，业务数据按租户与学生隔离。
4. 邀请码仍然保留，但主要用于高权限角色授予和受控家庭加入，不作为普通用户注册的唯一入口。
5. 所有学生均为未成年人；学生档案必须记录有效监护人同意，未完成同意前只能处于受限状态。
6. 手机号在界面、日志和运营查询中默认脱敏；用户可申请导出个人数据和注销账号。
7. 家庭可有多个学生档案；学习数据按家庭和学生双重作用域隔离。
8. 识别、判题、错因和推荐先作为候选，确认与确定性质量门后才成为正式记录。
9. 公开 MVP 必须跑通上传/录入、确认、判题、错题入本、推荐、分阶段复习和 PDF。
10. 推荐只使用已验证且授权允许的题；题量不足时展示缺口。
11. 用户授权的私有试题默认不跨租户复用。
12. 异步任务必须显示数据是否保存和下一步，并可从检查点恢复。

## 状态定义

- `拟议`：尚未确认，不能直接进入开发。
- `已确认`：产品范围已确定，可进入技术设计和任务拆分。
- `开发中`：已有负责人领取并开始实施。
- `待验收`：实现完成，等待按 PRD 验收。
- `已完成`：验收证据齐全并通过。
- `已阻塞`：存在明确外部依赖，已记录责任人和解除条件。

## 变更规则

- 修改产品范围时，必须同步更新本文件、讨论纪要和 PRD 的版本号、日期、需求状态。
- 技术实现不得把邀请码重新变成普通用户注册的强制前置条件。
- 成年人必须可完成“创建家庭”或“加入家庭”；学生只能通过监护邀请/档案绑定加入，不能创建家庭或成为所有者。
- 短信供应商、发送策略或合规要求变化时，需求编号保持稳定，在 PRD 的版本记录中补充变更。
