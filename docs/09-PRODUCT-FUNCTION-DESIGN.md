# Web 版产品功能设计

> 文档版本：v0.4.0
> 基线日期：2026-08-23
> 状态：产品基线已确认；核心视觉与交互规范见 10-UX-UI-INTERACTION-DESIGN.md，接口契约待后续工作项
> 上游：02-PRODUCT-REQUIREMENTS.md

## 1. 设计目标

把登录与注册边界讲清楚，同时保持注册后的零资料阻塞。已有账号使用验证码登录，新用户在独立页面完成手机号、验证码、密码和协议确认后自动登录；之后直接看到个人错题本，无身份选择、资料完善、家庭、学生档案、监护、实名或邀请码流程。

产品只有一种普通用户和一个服务端作用域：当前会话对应的 user_id。

## 2. 信息架构

| 一级入口 | 页面 | 责任 |
|---|---|---|
| 工作台 | P-WORKBENCH | 待确认、今日复习、处理中任务和近期错题 |
| 录入错题 | P-INTAKE-START、P-INTAKE-CONFIRM | 上传、切分并确认题目与作答 |
| 错题本 | P-ERROR-LIST、P-ERROR-DETAIL | 查找和查看正式错题 |
| 今日复习 | P-REVIEW-TODAY、P-REVIEW-ANSWER | 完成到期任务 |
| 练习与 PDF | P-PRACTICE、P-PDF-JOBS | 组织练习并生成 PDF |
| 学习进度 | P-PROGRESS | 展示用户自身趋势 |
| 设置与隐私 | P-SETTINGS、P-PRIVACY | 会话、导出和注销 |

不存在家庭、成员、学生、身份或角色切换入口。移动端保留“工作台、录入、错题本、复习、更多”，桌面端使用左侧导航。

## 3. 注册与首次进入

### 3.1 P-LOGIN 验证码登录

页面包含：

- 手机号；
- 发送验证码；
- 服务端要求时出现的 CAPTCHA；
- 验证码；
- 用户协议与隐私政策复选框；
- 登录按钮；
- “没有账号？立即注册”链接。

规则：

1. 登录场景只为已有账号发送验证码；未注册手机号提示前往注册，登录流程不得自动建号。
2. 倒计时只作体验提示，服务端是冷却和限流的事实源。
3. 供应商结果未知时不得提示用户立即重发。
4. 验证码填满只激活按钮，不自动提交；协议未勾选时前后端均拒绝登录。
5. 正确验证码消费后创建会话并跳转 P-WORKBENCH。
6. 点击注册链接时通过页面内导航状态回填合法手机号，不把手机号放入URL。

### 3.2 P-REGISTER 手机号注册

页面包含手机号、验证码、获取验证码、服务端按需显示的CAPTCHA、8—20位且同时包含英文字母和数字的密码及显示/隐藏按钮、协议复选框、注册按钮和“已有账号？去登录”。

规则：

1. 注册场景只服务新手机号；已注册手机号提示前往登录。
2. 注册验证码不能用于登录，登录验证码不能用于注册。
3. 注册成功在一个事务内消费验证码、创建账号、保存密码凭据和协议版本并建立会话。
4. 注册成功提示后自动进入 P-WORKBENCH。
5. 返回登录页时清空注册表单，不携带验证码或密码。
6. 密码默认隐藏，不在前端持久化；原文不得进入数据库、日志、审计或模型输入。

完整字段、按钮、错误、风控与状态标准见 `13-LOGIN-REGISTER-PRD.md`。

### 3.3 禁止出现的步骤

注册成功后不得出现：

- 姓名、昵称、年级、年龄或学习偏好表单；
- “你是谁”或身份选择；
- 家庭创建、家庭加入或邀请码；
- 学生档案；
- 监护人绑定或监护同意；
- 身份证、真实姓名、人脸或实名认证；
- 教师、家长、学生等角色选择。

### 3.4 首次空状态

新账号进入工作台后显示：

- 标题：开始建立你的错题本；
- 简短说明：上传一道错题，确认后即可获得分析和复习安排；
- 唯一主操作：录入第一道错题；
- 次操作：查看支持的文件格式。

不能用资料完善弹窗遮挡主操作。

## 4. 全局界面规则

### 4.1 当前账号

所有数据由服务端会话中的 user_id 确定。前端不提供用户作用域参数，不显示内部 user_id，也不能通过 URL 切换到其他用户。

### 4.2 全局任务中心

右上角展示处理中、待确认和失败任务数量。每项任务显示：

- 类型和创建时间；
- 当前状态或步骤；
- 数据是否已保存；
- 主操作。

无法准确估计时不显示虚假的剩余时间。

### 4.3 通用反馈

| 类型 | 用途 |
|---|---|
| 页面提示 | 推荐缺口、任务失败等持续状态 |
| 字段错误 | 紧邻当前输入并说明修正方式 |
| Toast | 已保存、已复制等短暂结果 |
| 确认对话框 | 注销、取消任务、移除错题等高影响操作 |
| 结果页 | 上传完成、正式入本、导出创建等流程终点 |

提示不得包含完整手机号、验证码、密码、挑战令牌、下载token、对象键、供应商正文或内部堆栈。

## 5. 工作台

### 5.1 单聊天流

工作台不再使用统计卡片和多栏面板，只保留一条从上到下的错题助手对话流。欢迎语、上传结果、用户已经确认的题干与作答、判题候选和入本结果按发生顺序出现；页面底部固定为唯一交互区。

错题数量、今日复习、学习进度和练习 PDF 均在对应独立页面查看。页面只有一个最强主操作：有待发送附件时为“发送”，有待确认内容时为当前确认操作。

会话窗口参考 Harness 的消息窗口原则，但不复制其代码或建立第二套聊天后端：

- 文字流只展示只读消息、结果和可折叠的处理记录，不得在消息正文中嵌入文本框或操作按钮；
- 上传、题干确认、作答确认、判题确认和入本操作复用页面底部同一个交互区，并按当前领域状态互斥切换；
- 桌面端整个错题助手主区域均接收文件拖放，拖入时覆盖显示明确的放置提示；粘贴图片继续在非编辑状态下全局可用；
- 首次只渲染最新 10 条消息；存在更早内容时显示“加载更早”，每次向前增加 10 条；
- 加载更早内容后保持原阅读锚点，不能把用户突然推到顶部或底部；
- 运行中的处理记录默认展开并逐步更新；成功或可恢复警告完成后折叠成一行摘要，错误保持展开；
- 用户确认后的题干与作答、模型候选和最终结果以普通只读消息留在会话中，避免表单状态冒充历史记录。

当前本地候选的会话窗口只管理本次页面生命周期中的显示窗口；文件、题干版本、作答、判题候选和错题条目仍由既有 MySQL 领域状态机持久化。刷新后的跨会话消息恢复属于后续能力，不能宣称已经完成。

### 5.2 状态

| 场景 | 主操作 |
|---|---|
| 新账号/无错题 | 在底部输入框添加第一份附件 |
| 有待确认 | 继续确认 |
| 有到期任务 | 开始今日复习 |
| 任务失败 | 查看失败原因与恢复方式 |
| 今天已完成 | 查看错题本 |
| 无合格推荐 | 重做原题或稍后查看 |

## 6. 错题录入

### 6.1 P-INTAKE-START

四个入口：

- 拍摄单题与作答；
- 上传单题图片；
- 上传整份试卷；
- 手工录入。

选择文件前展示允许格式、大小、用途、隐私和来源授权。

### 6.2 P-INTAKE-UPLOAD

每个文件显示预览、大小、类型和上传状态。

| 失败 | 处理 |
|---|---|
| 网络失败 | 保留本地选择，允许重试 |
| 类型或安全失败 | 不进入解析，说明允许格式 |
| 文件过大 | 提示压缩或拆分 |
| 重复内容 | 打开已有任务，不创建重复记录 |

### 6.3 P-INTAKE-SPLIT

整份试卷允许：

- 调整题目区域；
- 合并跨页题；
- 拆分错误区域；
- 排除封面、答案页和空白页；
- 保存草稿。

自动切分只是候选，进入分析前必须确认题目数量。

### 6.4 P-INTAKE-CONFIRM

逐题展示原图、题干、公式、作答和来源候选。主操作为“确认并分析”。

修改影响语义的内容创建新输入版本；旧分析立即标记过期。

## 7. 判题与正式入本

### 7.1 P-GRADE-WAIT

显示当前步骤：读取确认版本、分析作答、校验证据、等待确认。用户可以离开页面，任务在任务中心继续可见。

### 7.2 P-GRADE-RESULT

按顺序展示：

1. 正确、部分正确、错误或无法判断；
2. 第一处可证实错误；
3. 关联证据；
4. 错误阶段和错因候选；
5. 下一步行动；
6. 置信度与不确定项。

操作：

- 确认并加入错题本；
- 修正题干或作答；
- 补充步骤；
- 申请人工复核；
- 放弃分析。

“无法判断”必须提供重拍、补步骤或人工复核路径，不能写正式错题。

### 7.3 P-ERROR-COMMIT

提交前预览题目版本、判题、错因、标签和复习起点。提交幂等。成功后可立即重做、查看详情或继续录入。

## 8. 错题本

### 8.1 P-ERROR-LIST

支持按状态、知识点、错误阶段、来源、日期和是否到期筛选。默认按“最需要处理”排序。

卡片展示题目摘要、首错步骤、状态、最近作答和下一复习时间。

### 8.2 P-ERROR-DETAIL

分区：

- 题目与来源；
- 历次作答；
- 当前判题和错因；
- 推荐题；
- 复习阶段；
- 证据与版本；
- 移除等管理操作。

移除前展示影响，历史作答默认保留。恢复后重新计算未来任务，不复制旧任务。

## 9. 推荐与复习

### 9.1 推荐卡

每张卡必须解释：

- 来源错题；
- 匹配知识点或题型操作；
- 难度变化；
- 推荐原因；
- 是否做过。

“AI 推荐”不能作为唯一理由。没有合格题时展示缺口。

### 9.2 P-REVIEW-TODAY

显示预计题数和耗时。用户可调整今天数量；调整只推迟，不删除。

任务分为必做、建议和用户主动添加。

### 9.3 P-REVIEW-ANSWER

一次展示一道题。提交后进入与判题相同的确认流程，再显示阶段前进、保持、回退或等待复核。

打开答案不能自动标记完成。

## 10. 练习与 PDF

### 10.1 P-PRACTICE

练习来源：

- 今日复习；
- 错题筛选；
- 推荐题；
- 手工选择。

生成前检查重复、来源授权和题目验证状态。题量不足时允许生成较少内容并说明原因。

### 10.2 P-PDF-CONFIG

- 纸张固定 A4；
- 可调整题目顺序和留白；
- 答案版需要显式选择；
- 默认不打印。

### 10.3 P-PDF-JOBS

显示 processing、ready、failed 和 expired。就绪后提供短时下载；过期后重新验证当前账号并生成。

## 11. 学习进度

只展示当前账号自身趋势：

- 新增错题和已掌握数量；
- 知识点趋势；
- 错误阶段分布；
- 到期与逾期任务；
- 推荐缺口；
- 最近 7/30 天活动。

不做公开排名、跨用户比较或固定能力标签。样本不足时显示“数据不足”。

如某个筛选需要年级，年级只作为本次查询条件，不要求建立用户年级档案。

## 12. 设置与隐私

### 12.1 账号安全

- 当前会话和其他设备；
- 退出当前设备；
- 全端失效；
- 最近高风险操作。

不提供姓名、昵称、年级、年龄、身份、家庭或角色设置。

### 12.2 数据导出

创建前展示数据范围。任务状态为 pending、running、ready、failed 或 expired。下载时再次验证会话。

当前本地导出内容为业务 JSON 和文件元数据，不打包上传原始二进制；下载链接短时有效，最多下载 3 次，每次访问记录审计。未来若提供完整可携带包，必须另行定义 ZIP/manifest、原始文件授权和保留策略。

### 12.3 注销

流程：

1. 二次手机号验证；
2. 展示账号、错题、文件和任务影响；
3. 确认申请；
4. 展示处理状态。

注销后旧会话、业务逻辑访问、对象链接和任务恢复全部失效；账号停用并删除业务对象文件。认证、协议、审计等记录按数据分类策略受控留存，不将“注销”表述为无条件彻底删除所有数据。

## 13. 运营与人工复核

运营列表默认只显示内部 ID、脱敏主体、任务类型、错误分类、时间和状态，不显示用户资料，因为产品不采集这些资料。

查看题目正文或原图必须绑定工单、填写理由、限定时间并记录审计。

复核员只处理冻结审核包。提交前重新校验 user_id、输入版本和来源；已变化则拒绝提交。

## 14. 故障恢复

| 故障 | 用户看到 | 系统行为 | 操作 |
|---|---|---|---|
| 网络中断 | 上传暂停 | 不创建重复文件 | 重试 |
| 解析失败 | 原文件保存或明确拒绝 | 保留检查点和错误分类 | 重拍、手工录入或放弃 |
| 模型超时 | 暂无结果 | 不写正式库 | 稍后查看或复核 |
| 页面刷新 | 恢复任务和草稿 | 继续现有任务 | 继续流程 |
| Worker 重启 | 仍显示处理中 | 从检查点接管 | 无需重复提交 |
| 输入变化 | 旧结果过期 | 创建新任务 | 重新确认 |
| 账号注销 | 所有入口关闭 | 取消后续副作用 | 无 |

## 15. 响应式与无障碍

- 360 px 宽度下主流程无页面级横向滚动。
- 公式和大图允许独立缩放。
- 所有操作可使用键盘完成。
- 状态不只依靠颜色表达。
- 对话框正确管理焦点。
- 表单失败后聚焦第一个错误。
- 动画尊重减少动态效果设置。

## 16. 产品事件

| 事件 | 触发点 | 允许属性 |
|---|---|---|
| login_succeeded | 已有账号验证码登录并进入工作台 | 耗时、客户端版本 |
| registration_succeeded | 新账号注册并自动登录 | 耗时、协议版本 |
| intake_started | 选择录入方式 | 类型、文件数量 |
| intake_waiting_confirmation | 需要确认 | 原因分类、题目数量 |
| formal_error_created | 正式错题写入 | 错误阶段、是否复核 |
| review_started/completed | 开始/完成复习 | 阶段、题数、耗时 |
| recommendation_gap | 无足够合格题 | 筛选维度、缺口数 |
| pdf_job_changed | PDF 状态变化 | 状态、题数、耗时 |
| privacy_request_changed | 导出/注销变化 | 类型、状态、耗时 |

事件不得包含手机号、验证码、密码、挑战令牌、题目正文、原图地址、下载 token 或模型正文。

## 17. 关键验收场景

1. 新手机号完成验证码后直接进入空工作台，没有任何资料或身份步骤。
2. 新账号不填写昵称、年级、年龄或其他资料即可上传第一道题。
3. 整份试卷出现跨页题、答案页和模糊页时可修正切分。
4. 判题 unclear 时不创建正式错题，补充作答后创建新版本。
5. 推荐不足时展示缺口，所有已分配题均 verified 且授权允许。
6. Worker 在解析、判题和 PDF 阶段中断后无重复记录。
7. 用户 A 无法通过 URL、对象键、任务 ID 或导出访问用户 B 数据。
8. 导出链接过期后不能访问。
9. 注销后登录、文件链接和任务恢复均失败。
10. 全流程不出现家庭、成员、监护、实名、身份、昵称或年级必填入口。

## 18. 实现差异

v0.4.0 本地候选已完成独立 login/register 页面、挑战用途和 API、密码凭据与协议记录、user_id 授权边界、候选/正式质量门、推荐/复习/PDF、敏感导出和注销。真实 MySQL smoke、153 项测试、Codex CLI 数学候选实测及浏览器全流程已通过。

仍未达到生产目标的部分：真实短信/CAPTCHA/KMS/OSS、生产异步 OCR/AI Worker、PDF/DOCX 自动解析、PWA、运营后台、压测/灾备/观测和生产恢复。
