# 历史 PDF 拍照复习闭环

## 冻结需求（WEB-PDF-REVIEW-20260831）

- PDF 的生成日不等于复习完成日。实际判题提交日记录复习，下一次日期按现有六阶段规则计算。
- 新 PDF 保存题目、原错题、复习任务、阶段及到期时间快照；原题仅作推荐依据时不计为必交题。
- 分次拍照先累计必做题结果，全部齐备才汇总一次。最差结果决定 correct / partial / wrong。
- 正确、部分正确、错误的复习结果都只回写原任务，不重复创建错题；错因与知识点保留在冻结判题证据中。
- 题库交叉验证继续生效，冲突未解决或识别不清时不推进。
- 重复提交不重复推进；旧任务阶段或到期时间发生变化后不得影响新一轮任务。
- 归属不明时保留判题结果，允许在会话补充定位信息，不要求再次上传同一照片。

## 最小实现

复用 web_jobs.checkpoint_json 保存 PDF 的 review_manifest、逐题提交与权威回执。MySQL 中锁定 PDF 任务和对应复习任务，在同一事务内更新提交进度和既有 complete_review 状态机。不新增平行复习表或认证入口。

旧文件只从当前账户仍保留的 PDF 历史读取并验证文件哈希，根据印刷题号、阶段及当前仍有效的任务重建关联；不能唯一核实时提示补充 PDF 定位信息。已经删除的 PDF 历史不恢复、不参与匹配。

内部接口继续通过可信 Harness 会话绑定用户。模型只提交图片中读到的定位信息及判题结果；任务归属、必做数量、阶段推进和幂等均由服务端决定。

### 使用方式与边界

上传完成的旧 PDF 作答照片时说明“这是复习作答”，尽量拍全复习码/错题编号与完整题干。单条消息仍最多一张图片；同图中的必做原题和推荐题分别判题。识别到定位信息后可自动关联，不按 PDF 的生成日倒填复习记录。

新 PDF 原题是否必做沿用现有阶段规则；老 PDF 以原文件中的标记为准，没有“仅作推荐依据”标记时要求交齐原题。旧纸面缺少到期时间快照，因此仅当当前阶段吻合、任务到期时间不晚于原 PDF 生成时间、全部印刷推荐题可核实归属时才建立关联。不能确认、已删除历史、题库冲突或不清晰题目均不自动推进。

旧文件按当前账户最新 100 份限量检索；单文件最多 12 MiB / 100 页，每次最多读取约 32 MiB。范围外的文件需要指定 PDF 名称或任务编号。未匹配时可直接补充定位信息，由确认工具关联冻结判题结果，不需要重传图片。

同一纸面题目首次有效判定冻结；之后的订正不会覆盖这次复习结果，按回执安排下一轮订正复习。数据库异常返回可重试回执，原判题及错因/知识点仍保存于 grade_candidates。

本清单只覆盖本地实现和测试，不代表独立安全审查或生产部署批准。

## 逐题进度与重印共享（WEB-PDF-PROGRESS-20260831）

- 生成日的 PDF 卡片显示**截至当前**的已答/必做数量、待答、需订正、组内进度和逐题状态；不会把“整组完成 0”误作“尚未提交任何题”。
- 实际学习活动按首次有效提交的中国时间归属日期；例如 29 日 PDF 的一道推荐题在 31 日提交，则 29 日更新 PDF 进度，31 日增加一条已答题活动。原来的组完成日期和历史逾期快照不倒填。
- 重印通过原错题、复习任务、阶段、到期时间、题型、题库编号和题干快照识别同一练习。读取时合并已有有效提交，保留首次判定与时间；月份统计按题去重。同一天内容相同的重印卡片只展示一次。
- 写入时先锁定当前账号，再锁定其有效 PDF 和原复习任务，在事务内读取共享提交，只保存此次对应的 PDF。并发提交不同重印不会漏算或重复推进。发生异常时整笔回滚。
- 完成回执只在整组必做题集合一致的重印间共享；不同阶段、到期时间或题干不串用。单题正确不代表整组完成，所有必做题齐备后继续沿用原有阶段规则。
- 不修改历史 PDF 文件或原始提交，不扣额、不重新判题、不批量补写完成。已有冻结清单即时展示进度；旧文件没有可核对清单时明确提示“待核对”，不猜测零完成或全部完成。
- 本次未修改新推荐题的选题策略；同轮重印共享进度不等于跨轮推荐题绝不重复。
