# Web 版产品需求文档（PRD）

> 产品：李兆霖数学错题本 Web 版
> 文档版本：v0.3.1
> 基线日期：2026-08-22
> 状态：产品基线已确认；实现与验收状态以工作流证据为准

## 1. 产品愿景

为高中学生、家庭和受控教师提供一个可持续使用的数学错题学习服务：把试卷、题目或作答照片转化为经过确认的错题记录，给出有证据的判题与错因，安排复习并只从已验证题中推荐练习。

产品价值不是“保存图片”，而是完成以下闭环：

1. 可靠收集题目和学生作答；
2. 让用户确认系统识别结果；
3. 给出可复核的判题、首个错误步骤和下一步行动；
4. 将正式错题纳入复习计划；
5. 用已验证题补强薄弱环节；
6. 以工作台、练习任务和 PDF 支持持续复习。

## 2. 产品原则

1. 学习闭环优先：注册完成不等于产品完成，公开 MVP 必须跑通“错题进入—诊断—复习—再作答”。
2. 学生是数据主体：家庭、监护人和教师拥有不同管理权限，但不得把学生数据变成无边界的家庭共享数据。
3. 候选与事实分离：OCR、模型判题、错因和推荐均先作为候选；用户确认、确定性校验和对应质量门之后才成为正式记录。
4. 证据先于结论：判题至少关联题目版本、学生作答和分析依据；不清晰或冲突时明确进入待确认，不猜测。
5. 已验证题才能推荐：推荐缺口应如实展示，不用未验证、来源不明或不适配的题凑数。
6. 权利和隐私默认开启：学生监护同意、最小采集、导出、注销、审计和跨租户隔离不是上线后的补丁。
7. 原始材料可追溯：原图、识别候选、用户修订和正式版本分层保存，不覆盖原始证据。

## 3. 发布边界

### 3.1 公开 MVP 的两道门

公开 MVP 必须同时通过两道门，任一门未完成都不得对外宣称产品上线完成。

| 门禁 | 范围 | 完成结果 |
|---|---|---|
| GATE-A 账号与租户基础 | 手机验证码、会话、家庭、学生档案、监护同意、权限、导出和注销 | 用户能够安全进入自己的家庭与学生空间 |
| GATE-B 错题学习闭环 | 上传/录入、确认、判题、错因、错题本、推荐、复习任务和 PDF | 学生能够完成一次从错题进入到复习产物的闭环 |

当前注册模块的本地验收只属于 GATE-A 的部分工程证据，不代表任一道产品门已经通过。

### 3.2 MVP 包含

- 中国大陆手机号验证码注册与登录；
- 家庭租户、成员、学生档案和受控教师；
- 所有学生必需的监护同意和撤回；
- 单题图片、作答图片及整份试卷上传；
- 手工录入作为识别失败时的兜底；
- 题目切分、内容确认、判题、错因和正式错题记录；
- 仅基于已验证题的推荐；
- 即时下一步、分阶段复习任务和 A4 PDF；
- 学习工作台、任务状态、失败恢复、数据导出和注销；
- 最小运营后台、审计、告警与人工复核队列。

### 3.3 MVP 不包含

- 海外手机号、用户名密码或第三方社交登录；
- 多学校、多机构组织树、商业结算和公开题库市场；
- 学生之间的社区、排行榜或公开分享；
- 自动认定法定监护关系的外部实名服务；
- 由模型自动提交正式判题、正式题库或权限变更；
- 向其他租户分发仅具有“用户授权”来源的私有试题；
- 独立向量数据库；除非离线评测和 ADR 证明现有方案不足。

## 4. 用户、档案与数据归属

### 4.1 角色

| 角色 | 主要目标 | 默认边界 |
|---|---|---|
| 学生 | 未成年人；录入错题、查看诊断、完成复习 | 仅本人被绑定的学生档案；不能创建家庭或自批监护同意 |
| 监护人 | 成年人；管理学生监护同意并协助学习 | 仅明确关联的学生档案 |
| 家庭所有者 | 管理家庭、成员、邀请和所有权 | 不自动获得所有学生的敏感原图权限 |
| 教师/辅导者 | 指导被授权学生 | 必须按学生和权限范围授权，可随时撤销 |
| 平台运营 | 处理任务、风控和客服 | 默认脱敏，不进入家庭成员关系 |
| 内容审核员 | 复核题目、答案和来源 | 只能处理审核包，不查看不必要的学生身份 |
| 安全/审计人员 | 调查安全事件 | 临时授权、理由必填、全程审计 |

### 4.2 学生档案规则

1. 一个家庭可以创建多个学生档案。
2. 所有学生均按未成年人处理；产品不提供“成年学生”或“学生无需监护同意”分支。
3. 每个学生档案只属于一个家庭租户，所有错题、作答、复习和文件都必须带有该归属。
4. 学生档案由已验证的成年监护人创建，初始监护状态为 pending；监护同意 active 后才能处理学习数据。
5. 学生档案可以先由监护人管理而不绑定学生登录账号。
6. 学生手机号注册后只能接受监护关联或查看必要说明，不能自行创建家庭、创建学生档案或批准同意。
7. 学生登录用户在同一家庭最多绑定一个学生档案；不同家庭的数据不自动合并。
8. 绑定、解绑和跨家庭迁移属于高风险操作，必须二次验证、展示影响范围并产生审计。
9. 监护同意未生效或已撤回时，学生档案只能访问必要说明、监护邀请、退出和注销入口。

### 4.3 内容归属

| 内容类型 | 归属与复用规则 |
|---|---|
| 学生原图、作答、错因和学习记录 | 学生/家庭私有，不跨租户复用 |
| 用户上传试卷或题目 | 默认仅本租户使用，除非来源和授权允许更广使用 |
| 开放或已获得平台授权的题目 | 经内容审核和验证后可进入公共已验证题库 |
| 模型/OCR 输出 | 候选产物，不是正式题库或正式判题 |
| 练习 PDF 和导出包 | 按请求用户当时权限生成，短时下载 |

## 6. 核心用户旅程

### 6.1 首次开通

输入手机号 → 风控与验证码 → 首次身份创建 → 选择“成年监护人/其他成年角色”或“学生” → 成年人创建家庭或受邀加入 → 监护人创建学生档案并完成同意 → 可选绑定学生账号 → 进入工作台。

学生身份注册后不进入成年人家庭创建流程，而是进入受限状态，等待有效监护邀请、档案绑定和同意。产品不再询问“学生是否未成年”。

已有用户验证成功后恢复上次可用家庭和学生；存在多个可用空间时必须明确选择，不能由客户端任意指定租户获得权限。

### 6.2 错题学习闭环

选择学生 → 拍照/上传/手工录入 → 文件安全检查 → 题目切分与识别候选 → 用户确认题干和作答 → 判题候选 → 确认或申请复核 → 正式错题 → 即时下一步 → 推荐与复习计划 → 完成再作答 → 更新掌握状态。

### 6.3 复习与 PDF

进入今日复习 → 按阶段展示原题或推荐题 → 学生作答 → 判题与确认 → 更新阶段 → 可生成 A4 练习 PDF → 下载或打印由用户主动选择。

## 7. 功能需求

每项需求都必须满足租户隔离、监护状态、幂等、审计和候选/事实分离的公共约束。

### AUTH-001 手机验证码注册与登录

- 优先级：P0
- 状态：开发中

需求：

1. 支持中国大陆手机号的注册、登录和账号恢复统一入口。
2. 验证码短时有效、只保存安全摘要、一次性原子消费。
3. 对已注册和未注册手机号保持等价公开响应，防止账号枚举。
4. 登录签发可撤销会话，支持退出当前会话和全端失效。

验收：

- AC-AUTH-001-01：合法请求通过风控后产生一次发送，正确验证码仅成功消费一次。
- AC-AUTH-001-02：错误、过期、重复验证码失败且不暴露账号状态。
- AC-AUTH-001-03：重复验证同一规范化手机号不创建重复身份。
- AC-AUTH-001-04：退出及全端失效后旧会话不能访问受保护资源。

### AUTH-002 验证码风控与成本保护

- 优先级：P0
- 状态：开发中

需求：

1. 对手机号、精确 IP、IP 前缀、设备、租户和平台总量组合限流。
2. 风险升级 CAPTCHA，超限、预算耗尽或供应商异常时失败关闭。
3. 供应商超时或结果未知时禁止自动重发。
4. 日志不含完整手机号、验证码、密钥或请求体敏感字段。

验收：

- AC-AUTH-002-01：所有限流维度均有边界、并发和窗口竞争测试。
- AC-AUTH-002-02：超限请求不触发供应商调用；并发同幂等键最多受理一次。
- AC-AUTH-002-03：预算熔断、CAPTCHA 失败和供应商超时均有统一用户提示和审计。
- AC-AUTH-002-04：自动扫描确认日志和错误响应无敏感数据。

### AUTH-003 学生监护同意

- 优先级：P0
- 状态：待开发

需求：

1. 用户首次开通选择账户身份；选择学生即确定为未成年人，不再进行“是否未成年”的年龄分支。
2. 每个学生档案创建后均进入 guardian_consent_pending，不存在 not_required 状态。
3. 监护人使用独立的已验证成年人账号确认政策版本、关系声明和同意范围。
4. 学生不能创建或批准自己的监护同意。
5. 撤回同意后立即刷新权限并停止非必要处理。

验收：

- AC-AUTH-003-01：任何学生档案在同意 active 前都无法上传、解析、判题、推荐或发送学生内容给模型。
- AC-AUTH-003-02：学生会话不能伪造同意；同意记录可追溯且有版本。
- AC-AUTH-003-03：撤回后所有受限入口在权限传播目标内关闭。
- AC-AUTH-003-04：受限状态仍可访问政策、监护邀请、退出、导出/注销申请和客服。
- AC-AUTH-003-05：服务端不存在把学生档案标记为 not_required 或由学生自行转为 active 的路径。

### TENANT-001 家庭创建与所有权

- 优先级：P0
- 状态：开发中

需求：

1. 成年用户可幂等创建家庭并成为所有者。
2. 创建家庭和所有者成员关系在同一事务中完成。
3. 最后一名所有者退出前必须转移所有权或解散家庭。
4. 家庭解散与所有权转移必须二次验证、预览影响并审计。

验收：

- AC-TENANT-001-01：重复创建请求返回同一家庭，不产生孤立或重复关系。
- AC-TENANT-001-02：创建家庭和所有者关系原子完成，不产生无所有者家庭。
- AC-TENANT-001-03：最后一名所有者不能直接退出或注销。
- AC-TENANT-001-04：篡改 tenant_id 不能读取或修改其他家庭。

### TENANT-002 受控加入家庭

- 优先级：P0
- 状态：开发中

需求：

1. 已验证用户可使用有效邀请加入指定家庭。
2. 邀请绑定租户、角色、有效期、次数和可选目标手机号摘要。
3. 重复使用同一邀请必须幂等，不创建重复成员关系。
4. 学生加入家庭仍受监护同意约束，不能通过邀请切换为成年人角色。

验收：

- AC-TENANT-002-01：有效邀请仅授予签发记录中的家庭和角色。
- AC-TENANT-002-02：过期、撤销、超次数、租户或目标不匹配的邀请码均被拒绝。
- AC-TENANT-002-03：并发兑换最后一个名额不会超用。
- AC-TENANT-002-04：邀请不能绕过监护状态或学生作用域。

### AUTHZ-001 成员角色与高权限授予

- 优先级：P0
- 状态：待开发

需求：

1. 邀请原文仅在创建时显示，持久化使用不可逆摘要。
2. 教师、家庭管理权限和平台运营权限使用不同授权流程。
3. 教师授权必须选择学生和权限范围，默认只读。
4. 高权限授予、查看、变更、撤销和失败均进入安全审计。

验收：

- AC-AUTHZ-001-01：普通邀请不能通过修改请求提升为高权限角色。
- AC-AUTHZ-001-02：数据库和日志中不存在可直接使用的邀请码原文。
- AC-AUTHZ-001-03：教师不能访问未授权学生或未授权字段。
- AC-AUTHZ-001-04：撤销后新请求和已有对象链接立即失效。

### STUDENT-001 学生档案与作用域

- 优先级：P0
- 状态：开发中

需求：

1. 家庭可创建、选择和停用多个学生档案。
2. 学生档案显示姓名/昵称、年级、当前学习阶段和监护状态；不默认采集身份证件。
3. 所有学习入口必须先确定当前家庭和学生，切换时清空上一作用域的缓存与草稿引用。
4. 绑定登录学生必须经过双方可验证流程；解绑不删除历史记录。

验收：

- AC-STUDENT-001-01：同一请求不能把文件、错题或任务写入另一学生。
- AC-STUDENT-001-02：跨租户和跨学生读取、导出、任务恢复测试全部拒绝。
- AC-STUDENT-001-03：停用档案不可新增学习数据，但保留依法可访问的历史和权利入口。

### INTAKE-001 题目与作答采集

- 优先级：P0
- 状态：开发中

需求：

1. 支持单题图片、作答图片、整份 PDF/图片试卷和手工录入。
2. 上传前展示允许格式、大小、用途和隐私提示；上传后先进入隔离状态。
3. 文件通过类型、大小和安全检查后才进入解析；失败时保留可理解的原因和下一步。
4. 上传使用幂等键和内容哈希，网络重试不产生重复文件或重复扣费任务。
5. 用户必须声明来源类型和使用授权范围。

验收：

- AC-INTAKE-001-01：伪造扩展名、超限、损坏、恶意和跨租户对象均被拒绝。
- AC-INTAKE-001-02：重复上传同一内容不会生成重复正式记录。
- AC-INTAKE-001-03：识别失败时可重拍、重新选择区域或切换手工录入。
- AC-INTAKE-001-04：原始文件不可被后续候选覆盖，删除和保留遵循文件生命周期。

### INTAKE-002 试卷切分与内容确认

- 优先级：P0
- 状态：待开发

需求：

1. 整份试卷产生题目切分候选，用户可调整区域、合并、拆分和排除非题目页面。
2. 每题展示题干、选项、公式、图形、来源和学生作答候选。
3. 用户确认后冻结一个输入版本；修改内容创建新版本并使旧分析失效。
4. 图像不清、页缺失、题目答案冲突时进入 needs_confirmation。

验收：

- AC-INTAKE-002-01：固定样本集可逐题核对切分结果，漏题和重复题可被用户修正。
- AC-INTAKE-002-02：未确认候选不能进入正式错题或推荐。
- AC-INTAKE-002-03：确认后修改题干会触发重新判题，不复用旧结论。

### GRADE-001 判题、首错步骤与人工确认

- 优先级：P0
- 状态：待开发

需求：

1. 对已冻结的题目版本和作答生成 correct、partial、incorrect 或 unclear 候选。
2. 非正确结果应尽量定位首个可证实错误步骤、错误阶段和改进建议。
3. 结论展示证据引用、置信度和不确定项；复杂证明、图像不清或答案冲突必须进入复核。
4. 用户可确认、修正作答识别、补充步骤或申请人工复核。
5. 模型候选不能直接修改正式错题、掌握状态或分数。

验收：

- AC-GRADE-001-01：固定基准集分别统计正确、部分正确、错误和不清晰表现。
- AC-GRADE-001-02：输入版本变化、证据缺失或低置信度时拒绝正式提交。
- AC-GRADE-001-03：确认后的正式判题保留候选、修订和确认者审计链。
- AC-GRADE-001-04：同一提交幂等，重复任务不会生成重复作答或错题。

### ERROR-001 正式错题本

- 优先级：P0
- 状态：待开发

需求：

1. 正式错题包含题目版本、学生作答、判题、首错步骤、错因、知识点、来源和下一次复习时间。
2. 支持 open、reviewing、mastered 和 removed 状态，状态变化必须由可解释事件驱动。
3. 学生可按状态、知识点、来源、日期和错误阶段筛选。
4. 删除展示影响范围；默认进入可恢复移除状态，不静默破坏复习历史。

验收：

- AC-ERROR-001-01：只有确认后的判题可以创建或更新正式错题。
- AC-ERROR-001-02：重复题合并不丢失不同作答与时间线。
- AC-ERROR-001-03：筛选和统计始终限制在当前租户和学生。
- AC-ERROR-001-04：mastered 必须有完成复习或人工确认依据。

### RECOMMEND-001 即时下一步与推荐题

- 优先级：P0
- 状态：待开发

需求：

1. 错题确认后立即给出一个明确下一步：重做原题、查看提示、补基础或进入复核。
2. 推荐只从已验证且授权可用的题目中召回。
3. 推荐按知识点、题型操作、难度、错误阶段和重复项过滤。
4. 数量不足时显示缺口，不用低质量题填满目标数量。
5. 推荐候选经质量门后才能分配给学生。

验收：

- AC-RECOMMEND-001-01：候选中不存在未验证、越权来源、答案冲突或重复题。
- AC-RECOMMEND-001-02：每项推荐可解释与哪个错题、薄弱点和筛选规则相关。
- AC-RECOMMEND-001-03：固定基准集记录 Top-K 命中、冲突、重复和缺口率。

### REVIEW-001 分阶段复习计划

- 优先级：P0
- 状态：待开发

需求：

1. 每个正式错题生成可配置的复习阶段，阶段可以使用原题、变式题或混合任务。
2. 今日复习按到期时间、风险和预计耗时排序，允许用户调整当天数量但不静默丢弃到期项。
3. 完成作答后根据结果推进、保持或回退阶段，并记录原因。
4. 缺题、任务失败或长期逾期时给出明确处理方式。

验收：

- AC-REVIEW-001-01：重复调度不会生成重复阶段任务。
- AC-REVIEW-001-02：阶段变化可追溯到作答或人工操作。
- AC-REVIEW-001-03：跨时区、跨日、逾期和恢复场景结果确定。
- AC-REVIEW-001-04：未完成任务不会被新计划静默覆盖。

### PDF-001 练习 PDF

- 优先级：P0
- 状态：待开发

需求：

1. 用户可从今日复习、筛选结果或选中错题生成 A4 练习 PDF。
2. 默认不含答案且不自动打印；答案版需要显式选择和权限确认。
3. 生成任务幂等，显示 processing、ready、failed、expired 状态。
4. 下载链接短时有效，可重新生成；PDF 内容与任务快照一致。

验收：

- AC-PDF-001-01：12 题及以上混合包逐页视觉检查无裁切、重叠和不可读公式。
- AC-PDF-001-02：相同输入快照重复生成具有相同内容哈希。
- AC-PDF-001-03：下载和重新生成均执行实时权限检查并记录审计。

### CONTENT-001 题库来源、版本与验证

- 优先级：P0
- 状态：开发中

需求：

1. 每题具有来源、授权状态、内容哈希、版本和验证状态。
2. 题干、答案或解析变化创建新版本，不覆盖旧版本证据。
3. 候选题通过确定性校验和内容审核后才可标记 verified。
4. 用户授权私有内容默认只服务该租户；跨租户复用必须具有明确授权。
5. 桌面 SQLite 仅通过只读抽取、哈希对账和受控迁移进入独立 MySQL。

验收：

- AC-CONTENT-001-01：未验证或来源不允许的题不能进入推荐和公共题库。
- AC-CONTENT-001-02：迁移两次总数、内容哈希和关联结果一致。
- AC-CONTENT-001-03：版本变更不会改变历史作答所引用的题目快照。
- AC-CONTENT-001-04：来源撤回或版权限制可停止后续分发且保留必要审计。

### JOB-001 异步任务与恢复体验

- 优先级：P0
- 状态：待开发

需求：

1. 上传解析、审核、判题、推荐、导出和 PDF 使用可恢复任务。
2. 用户可查看 queued、running、waiting_confirmation、ready、failed 和 cancelled。
3. 每个失败状态显示可重试性、已保留内容和下一步，不暴露内部堆栈。
4. 重试从最近成功检查点继续，不重复调用模型、扣费或写正式数据。

验收：

- AC-JOB-001-01：Worker 中断、重复投递和数据库短暂故障后可恢复。
- AC-JOB-001-02：取消后不再产生新的正式副作用，已完成步骤有明确保留规则。
- AC-JOB-001-03：输入快照变化创建新任务，不错误复用旧候选。

### WORKBENCH-001 学习工作台

- 优先级：P0
- 状态：待开发

需求：

1. 工作台展示当前家庭/学生、待确认、今日复习、处理中任务、近期错题和推荐缺口。
2. 第一主操作始终指向当前最需要的下一步。
3. 所有卡片同时支持空状态、加载、失败、受限和无权限状态。
4. 移动端优先，桌面端支持高效筛选和批量生成 PDF。

验收：

- AC-WORKBENCH-001-01：新用户、无错题、处理中、逾期、受限账号都有明确下一步。
- AC-WORKBENCH-001-02：切换学生后页面、草稿和后台任务引用不串号。
- AC-WORKBENCH-001-03：键盘操作、焦点、对比度和表单错误达到无障碍目标。

### PRIV-001 敏感数据保护

- 优先级：P0
- 状态：开发中

需求：

1. 页面、日志、审计导出和错误默认显示脱敏手机号。
2. 验证码、邀请原文、下载 token 和密钥不得明文持久化或进入普通日志。
3. 模型输入必须先通过租户授权、监护状态和必要性检查。
4. 原图、导出包和 PDF 使用短时访问授权。

验收：

- AC-PRIV-001-01：敏感数据扫描覆盖 API、任务、运营查询和异常日志。
- AC-PRIV-001-02：无权限角色只能看到脱敏或最小必要信息。
- AC-PRIV-001-03：候选包和模型审计不含手机号、验证码、密钥或不必要学生身份。

### PRIV-002 个人数据导出

- 优先级：P0
- 状态：待开发

需求：

1. 二次验证后可申请导出本人依法且按当前权限可访问的数据。
2. 导出包异步生成、短时下载，不包含其他成员私有内容和内部安全字段。
3. 监护人代学生导出时必须验证当前有效关系和范围。
4. 任务失败可安全重试，下载时再次检查权限并记录审计。

验收：

- AC-PRIV-002-01：导出具有身份、租户、学生和监护关系负向测试。
- AC-PRIV-002-02：下载过期、次数限制和每次访问审计有效。
- AC-PRIV-002-03：导出包不包含其他成员私有内容、内部安全字段或过期权限数据。
- AC-PRIV-002-04：失败重试不扩大数据范围或产生重复通知。

### PRIV-003 账号注销

- 优先级：P0
- 状态：待开发

需求：

1. 二次验证后可申请注销，并看到数据和家庭关系的影响范围。
2. 唯一所有者必须先转移所有权或解散家庭。
3. 注销执行时撤销全部会话、停止非必要处理并取消不应继续的任务。
4. 各类数据按批准策略删除、匿名化或受控留存，并生成执行报告。

验收：

- AC-PRIV-003-01：未通过二次验证或仍为唯一所有者的请求被阻止。
- AC-PRIV-003-02：注销后的登录、任务恢复和文件下载均失败。
- AC-PRIV-003-03：删除、匿名化和受控留存按数据类别可证明。
- AC-PRIV-003-04：注销不会静默删除其他成员拥有的家庭共享数据。

### OPS-001 运营与人工复核

- 优先级：P0
- 状态：待开发

需求：

1. 提供风控、短信预算、失败任务、待确认内容、题库质量和数据权利工单视图。
2. 运营默认只见脱敏信息；查看敏感信息需要临时审批、理由和审计。
3. 人工复核不能绕过租户归属、输入版本、来源授权和幂等质量门。

验收：

- AC-OPS-001-01：运营角色不能直接修改验证码、会话、正式判题或数据库。
- AC-OPS-001-02：人工复核结果保留操作者、证据、版本和时间。
- AC-OPS-001-03：高风险批量操作满足双人原则并可回滚。

## 8. 通用状态和异常体验

### 8.1 异步任务状态

| 状态 | 用户含义 | 可用操作 |
|---|---|---|
| queued | 已收到，等待处理 | 查看、取消 |
| running | 正在处理 | 查看进度、取消后续步骤 |
| waiting_confirmation | 需要用户确认识别或结论 | 查看、修正、确认 |
| ready | 结果可用 | 进入结果、下载或继续学习 |
| failed_retryable | 暂时失败且可重试 | 从检查点重试 |
| failed_final | 无法自动完成 | 手工录入、联系客服或放弃 |
| cancelled | 已取消 | 查看保留内容、重新开始 |
| expired | 下载或临时结果过期 | 重新验证权限并生成 |

### 8.2 通用错误原则

- 文案说明“发生了什么、数据是否保存、下一步是什么”。
- 不展示堆栈、供应商正文、账号存在性或权限内部细节。
- 同一错误具有稳定错误码，前端不得按自由文本推断业务状态。
- 任何失败不得把候选误标为正式结果。
- 用户重复点击、网络重试和刷新不得产生重复正式记录。

## 10. 产品指标

### 10.1 核心漏斗

| 指标 | 定义 | MVP 观察目标 |
|---|---|---|
| 家庭落位完成率 | 验证手机号后完成家庭和学生选择的用户占比 | 建立基线，持续排查异常流失 |
| 首题闭环完成率 | 开始上传后得到正式错题和下一步的占比 | 不低于验收样本 90% |
| 待确认解决率 | waiting_confirmation 在 24 小时内被处理的占比 | 不低于 80% |
| 今日复习完成率 | 到期任务中当天完成的占比 | 建立基线并按学生自我对比 |
| 推荐缺口率 | 需要推荐但无合格题的请求占比 | 必须真实记录，不以低质量题降低 |
| 人工复核率 | 正式判题中需要人工处理的占比 | 用于质量和成本规划，不设越低越好 |

学习效果指标只做学生自身纵向比较，不做公开排名，不用于自动给学生贴不可撤销标签。

### 10.2 服务体验目标

- 常规页面查询在目标网络条件下 P95 不高于 500 ms。
- 不含外部供应商的同步写操作 P95 不高于 1 秒。
- 异步任务必须在 2 秒内返回已受理状态；实际完成时间按任务类型单独设 SLO。
- 生产关键路径月度可用性目标为 99.9%，具体错误预算在运维文档冻结。
- 支持当前主流 Chrome、Edge、Safari 的最近两个大版本；移动端宽度 360 px 起可用。
- 核心学习流程以 WCAG 2.2 AA 为无障碍目标。

## 11. 分析事件与隐私

允许记录的产品事件包括：家庭落位完成、上传开始/成功/失败、等待确认、正式错题创建、复习开始/完成、PDF 生成和导出/注销状态变化。

事件只使用内部主体 ID、租户伪标识、任务类型、状态、耗时和错误分类；禁止写入手机号、验证码、题目正文、学生姓名、原图地址、下载 token 或模型完整输入输出。

## 12. 产品策略配置

以下参数必须版本化、可审计并在上线前由对应负责人确认，不能散落在客户端：

| 参数 | 产品默认 | 最终批准角色 |

## 13. MVP 上线门禁

1. GATE-A 和 GATE-B 的全部 P0 需求均有实现、自动化或可复现验收证据。
2. 至少完成一次从注册、家庭落位、上传错题、确认、判题、推荐、复习到 PDF 的生产等价端到端演练。
3. 验证码攻击、跨租户访问、学生绕过监护同意、恶意文件、重复任务、模型失败、导出越权和注销残留专项测试通过。
4. 未验证题、来源不允许题和低置信度候选无法进入推荐或正式题库。
5. 原始证据、候选、用户修订和正式记录之间可追溯。
6. 权限矩阵覆盖 API、后台任务、对象键、导出和运营后台。
7. 产品策略配置获得对应负责人批准；高风险变更满足双人原则。
8. 本地全链路、安全复核和恢复演练通过后，才能由用户人工批准云部署。
