# Web 版产品需求文档（PRD）

> 产品：李兆霖数学错题本 Web 版
> 文档版本：v0.4.0
> 基线日期：2026-08-23
> 状态：产品基线已确认；实现与验收状态以工作流证据为准

## 1. 产品定义

这是一个个人数学错题本。已有账号使用手机号验证码登录；新用户通过独立注册页提交手机号、验证码和密码并确认协议，注册成功自动登录。用户进入后立即使用自己的错题本，不需要选择身份、创建家庭、绑定监护人、接受邀请或完成实名认证。

产品主闭环：

验证码登录或完成注册 → 进入工作台 → 上传或录入题目与作答 → 确认识别结果 → 查看判题和首错步骤 → 正式加入错题本 → 获得推荐与复习任务 → 生成练习 PDF。

## 2. MVP 核心原则

1. 注册后直接使用：新用户完成手机号验证、密码设置和协议确认后即拥有一个可用账号、会话和私有错题本。
2. 只有一种普通用户：系统不区分学生、家长、教师、家庭所有者或其他前台身份。
3. 一账号一错题本：所有用户学习数据直接归属 user_id，不需要家庭或学生档案中间层。
4. 不做实名认证：不采集身份证、人脸、真实姓名或法定监护关系证明。
5. 不做年龄判断：不询问年龄或未成年人状态，不设置监护同意门。
6. 候选与事实分离：OCR、切分、判题、错因和推荐先作为候选，确认与确定性质量门后才写正式记录。
7. 已验证题才能推荐：没有合格题时显示缺口，不用未验证或来源不允许的题凑数。
8. 用户内容默认私有：原图、作答、错因和上传题目不跨账号复用。
9. 原始证据可追溯：原图、候选、用户修订和正式版本分层保存，不覆盖原始材料。

## 3. MVP 范围

### 3.1 包含

- 独立的中国大陆手机号注册页、验证码登录页、页面跳转、退出和会话撤销；
- 注册密码安全存储、用户协议与隐私政策版本确认；
- 验证码限流、CAPTCHA、预算保护和账号存在性查询防滥用；
- 注册成功后直接进入空错题本；
- 单题图片、作答图片和整份试卷上传；
- 手工录入作为识别失败时的兜底；
- 题目切分、题干/作答确认、判题、首错步骤和错因；
- 正式错题本、筛选、时间线和掌握状态；
- 仅使用已验证题的推荐；
- 分阶段复习任务和 A4 PDF；
- 任务状态、失败恢复、数据导出和账号注销；
- 最小运营后台、内容审核和安全审计。

### 3.2 暂不包含

- 家庭、家庭所有者、家庭成员和家庭邀请码；
- 学生档案、家长/监护人绑定和监护同意流程；
- 教师、辅导者或其他普通用户角色；
- 身份选择、年龄判断、身份证、实名或人脸认证；
- 多学校、多机构组织树、公开社区和排行榜；
- 用户间共享、协作、转移错题本或代管账号；
- 由模型自动提交正式判题、正式题库、权限变更或生产发布；
- 向其他账号复用仅有用户授权的私有试题；
- 密码登录、忘记密码和密码找回；注册密码仅作为已保存凭据，在对应产品需求获批前不展示未实现入口；
- 独立向量数据库，除非离线评测和 ADR 证明现有方案不足。

## 4. 用户与数据模型

### 4.1 唯一前台用户模型

所有注册账号具有相同的前台能力：

- 使用自己的错题本；
- 上传和确认自己的材料；
- 查看自己的判题、推荐、复习和 PDF；
- 导出或注销自己的账号数据。

用户不填写姓名、昵称、年级、身份、年龄或学习偏好。系统不建立个人资料完善流程；如某次练习需要年级条件，只作为该次任务参数，不保存为必填账号档案。

### 4.2 数据归属

| 数据 | 归属与规则 |
|---|---|
| 原图、作答、错因、错题和复习记录 | 归属当前 user_id，其他普通用户不可访问 |
| 用户上传试卷或题目 | 默认仅当前 user_id 使用 |
| 开放或平台已授权题目 | 经审核和验证后可进入公共已验证题库 |
| OCR/模型输出 | 候选产物，不是正式题库或正式判题 |
| PDF 和导出包 | 按请求时的 user_id 权限生成，短时下载 |

所有 API、后台任务、对象键、导出和审计查询必须以服务端会话解析的 user_id 为边界，不能相信客户端提交其他用户 ID。

### 4.3 最小权限

| 对象/操作 | 当前用户 | 运营/审核 |
|---|---|---|
| 查看或修改账号设置 | 仅本人 | 默认不可修改 |
| 上传、确认和查看原图 | 仅本人 | 仅故障/审核最小范围临时访问 |
| 查看错题、作答和复习 | 仅本人 | 默认不可见正文 |
| 确认候选并写正式错题 | 仅本人触发，服务端质量门提交 | 不可代替用户直接提交 |
| 内容验证 | 不允许修改公共验证状态 | 内容审核角色按审核包处理 |
| 导出和注销 | 仅本人二次验证后发起 | 经审批处理异常工单 |

## 5. 首次使用与核心流程

### 5.1 首次使用

已有账号：进入登录页 → 输入手机号 → 发送前风控 → 输入验证码并确认协议 → 创建会话 → 进入工作台。

新账号：进入注册页 → 输入手机号 → 发送前风控 → 输入验证码和密码并确认协议 → 原子创建账号、凭据和会话 → 进入工作台。

首次工作台显示空状态和唯一主操作“录入第一道错题”。系统不得要求用户先填写昵称、年级、身份、家庭、邀请码或监护信息。

### 5.2 错题学习闭环

拍照/上传/手工录入 → 文件安全检查 → 题目切分与识别候选 → 用户确认题干和作答 → 判题候选 → 用户确认或申请复核 → 正式错题 → 即时下一步 → 推荐与复习计划 → 再作答 → 更新掌握状态。

### 5.3 复习与 PDF

进入今日复习 → 完成原题或推荐题 → 确认判题 → 更新复习阶段 → 可生成 A4 练习 PDF → 用户主动下载或打印。

## 6. 功能需求

每项需求都必须满足 user_id 隔离、幂等、审计、输入版本校验和候选/事实分离。

### ACCOUNT-001 独立注册并自动登录

- 优先级：P0
- 状态：本地已验收（v0.4.0）；生产安全门禁未完成

需求：

1. 注册页提交手机号、验证码、8—20位且同时包含英文字母和数字的密码，以及生效协议版本。
2. 验证成功后原子创建账号、密码凭据、协议确认记录和会话。
3. 新账号立即拥有一个空错题本，不需要任何身份或组织落位。
4. 注册成功自动登录，首次响应直接给出工作台入口和“录入第一道错题”主操作。

验收：

- AC-ACCOUNT-001-01：新用户完成注册表单后不经过资料、身份或组织门即可访问工作台和上传入口。
- AC-ACCOUNT-001-02：重复提交同一手机号不会创建重复账号、凭据或错题本。
- AC-ACCOUNT-001-03：注册后不要求填写昵称、年级、身份、家庭、监护或其他个人资料。
- AC-ACCOUNT-001-04：用户只能访问服务端会话对应的个人错题本。
- AC-ACCOUNT-001-05：密码原文不进入数据库、日志、审计、分析或模型输入；哈希方案和密钥管理通过安全复核。
- AC-ACCOUNT-001-06：未确认当前用户协议和隐私政策时，前后端均拒绝注册。

### AUTH-001 手机验证码登录

- 优先级：P0
- 状态：本地已验收；真实供应商与生产门禁未完成

需求：

1. 登录页只为已有账号申请 `purpose=login` 的验证码挑战。
2. 验证码短时有效、只保存安全摘要并一次性原子消费。
3. 未注册手机号提示前往注册；已注册账号正常建立会话。
4. 登录前必须确认用户协议和隐私政策。
5. 登录签发可撤销会话，支持退出当前会话和全端失效。

验收：

- AC-AUTH-001-01：合法登录请求通过风控后产生一次发送，正确验证码仅成功消费一次。
- AC-AUTH-001-02：错误、过期、取消、跨手机号、跨场景和重复验证码均失败，并返回稳定错误码。
- AC-AUTH-001-03：登录流程绝不为未注册手机号创建账号。
- AC-AUTH-001-04：退出及全端失效后旧会话不能访问受保护资源。
- AC-AUTH-001-05：登录页与注册页相互跳转符合手机号回填与注册表单清空规则。

### AUTH-002 验证码风控与成本保护

- 优先级：P0
- 状态：本地已验收；生产化未完成

需求：

1. 对手机号、精确 IP、IP 前缀、设备、业务场景、账号和平台总量组合限流；同手机号为5次/小时、10次/滚动24小时。
2. 风险升级 CAPTCHA，超限、预算耗尽或供应商异常时失败关闭。
3. 供应商超时或结果未知时禁止自动重发。
4. 日志不含完整手机号、验证码、密码、密钥或请求体敏感字段。

验收：

- AC-AUTH-002-01：所有限流维度均有边界、并发和窗口竞争测试。
- AC-AUTH-002-02：超限请求不触发供应商调用；并发同幂等键最多受理一次。
- AC-AUTH-002-03：预算熔断、CAPTCHA 失败和供应商超时有稳定用户提示和审计；供应商结果未知不自动重发。
- AC-AUTH-002-04：自动扫描确认日志和错误响应无敏感数据。
- AC-AUTH-002-05：登录/注册场景切换、刷新、换设备和并发请求不能绕过手机号与平台合并预算。
- AC-AUTH-002-06：账号存在性明确反馈必须通过批量枚举攻击测试和独立安全复核。

### INTAKE-001 题目与作答采集

- 优先级：P0
- 状态：开发中

需求：

1. 支持单题图片、作答图片、整份 PDF/图片试卷和手工录入。
2. 上传前展示允许格式、大小、用途和隐私提示；上传后先进入隔离状态。
3. 文件通过类型、大小和安全检查后才能解析。
4. 上传使用幂等键和内容哈希，网络重试不产生重复文件或重复任务。
5. 用户必须声明材料来源和使用授权范围。

验收：

- AC-INTAKE-001-01：伪造扩展名、超限、损坏、恶意和跨用户对象均被拒绝。
- AC-INTAKE-001-02：重复上传同一内容不会生成重复正式记录。
- AC-INTAKE-001-03：识别失败时可重拍、重新选择区域或手工录入。
- AC-INTAKE-001-04：原始文件不被候选覆盖，删除和保留遵循文件生命周期。

### INTAKE-002 试卷切分与内容确认

- 优先级：P0
- 状态：本地手工确认已验收；自动切分延期

需求：

1. 整份试卷产生切分候选，用户可调整、合并、拆分和排除页面。
2. 每题展示题干、公式、图形、来源和作答候选。
3. 用户确认后冻结输入版本；修改内容创建新版本并使旧分析失效。
4. 图像不清、页缺失或答案冲突时进入 waiting_confirmation。

验收：

- AC-INTAKE-002-01：固定样本可逐题核对，漏题和重复题可修正。
- AC-INTAKE-002-02：未确认候选不能进入正式错题或推荐。
- AC-INTAKE-002-03：修改题干或作答后必须重新判题。

### GRADE-001 判题、首错步骤与确认

- 优先级：P0
- 状态：本地手工判题已验收；自动 OCR/AI Worker 延期

需求：

1. 对冻结的题目版本和作答生成 correct、partial、incorrect 或 unclear 候选。
2. 非正确结果应定位首个可证实错误步骤、错误阶段和改进建议。
3. 结论展示证据、置信度和不确定项；复杂证明或冲突进入复核。
4. 用户可确认、修正识别、补充步骤或申请人工复核。
5. 模型候选不能直接修改正式错题、掌握状态或分数。

验收：

- AC-GRADE-001-01：固定基准集分别统计四类结论表现。
- AC-GRADE-001-02：输入变化、证据缺失或低置信度时拒绝正式提交。
- AC-GRADE-001-03：正式判题保留候选、修订和确认审计链。
- AC-GRADE-001-04：重复任务不会生成重复作答或错题。

### ERROR-001 正式错题本

- 优先级：P0
- 状态：本地已验收

需求：

1. 正式错题包含题目版本、作答、判题、首错步骤、错因、知识点、来源和下次复习时间。
2. 支持 open、reviewing、mastered 和 removed 状态。
3. 支持按状态、知识点、来源、日期和错误阶段筛选。
4. 移除错题前展示影响，默认保留可追溯历史。

验收：

- AC-ERROR-001-01：只有确认后的判题可以创建或更新正式错题。
- AC-ERROR-001-02：重复题合并不丢失不同作答与时间线。
- AC-ERROR-001-03：筛选和统计始终限制在当前 user_id。
- AC-ERROR-001-04：mastered 必须有完成复习或用户确认依据。

### RECOMMEND-001 即时下一步与推荐题

- 优先级：P0
- 状态：本地已验收；权威题库已同步，生产回滚演练待完成

需求：

1. 错题确认后立即给出重做、提示、补基础或复核等明确下一步。
2. 推荐只从已验证且授权可用的题目中召回。
3. 按知识点、题型操作、难度、错误阶段和重复项过滤。
4. 数量不足时显示缺口，不用低质量题填满。
5. 推荐候选经质量门后才能分配。

验收：

- AC-RECOMMEND-001-01：没有未验证、来源不允许、答案冲突或重复题。
- AC-RECOMMEND-001-02：每项推荐可解释与哪道错题和筛选规则相关。
- AC-RECOMMEND-001-03：固定基准集记录 Top-K、冲突、重复和缺口率。

### REVIEW-001 分阶段复习计划

- 优先级：P0
- 状态：本地已验收

需求：

1. 每个正式错题生成可配置复习阶段。
2. 今日复习按到期时间、风险和预计耗时排序。
3. 用户可调整当天数量，但系统不静默删除到期项。
4. 作答结果推动阶段前进、保持或回退并记录原因。

验收：

- AC-REVIEW-001-01：重复调度不会生成重复阶段任务。
- AC-REVIEW-001-02：阶段变化可追溯到作答或用户操作。
- AC-REVIEW-001-03：跨日、逾期和恢复场景结果确定。
- AC-REVIEW-001-04：未完成任务不被新计划静默覆盖。

### PDF-001 练习 PDF

- 优先级：P0
- 状态：本地已验收

需求：

1. 用户可从今日复习、筛选结果或选中错题生成 A4 PDF。
2. 默认不含答案且不自动打印；答案版需要显式选择。
3. 生成任务幂等并显示 processing、ready、failed、expired。
4. 下载链接短时有效，可重新生成。

验收：

- AC-PDF-001-01：12 题以上混合包逐页检查无裁切、重叠和不可读公式。
- AC-PDF-001-02：相同输入快照重复生成具有相同内容哈希。
- AC-PDF-001-03：下载和重新生成均执行当前 user_id 权限检查。

### CONTENT-001 题库来源、版本与验证

- 优先级：P0
- 状态：本地质量门及权威题库同步已验收；生产回滚演练待完成

需求：

1. 每题具有来源、授权状态、内容哈希、版本和验证状态。
2. 题干、答案或解析变化创建新版本。
3. 候选题经过确定性校验和内容审核后才能标记 verified。
4. 用户私有内容默认只服务该用户，跨用户复用必须具有明确授权。
5. 桌面 SQLite 仅通过只读抽取、哈希对账和受控迁移进入独立 MySQL。

验收：

- AC-CONTENT-001-01：未验证或来源不允许的题不能进入推荐和公共题库。
- AC-CONTENT-001-02：迁移两次的总数、哈希和关联结果一致。
- AC-CONTENT-001-03：版本变化不改变历史作答引用的快照。
- AC-CONTENT-001-04：来源撤回可停止后续分发并保留必要审计。

### JOB-001 异步任务与恢复体验

- 优先级：P0
- 状态：本地可恢复任务已验收；生产 Worker 延期

需求：

1. 上传解析、审核、判题、推荐、导出和 PDF 使用可恢复任务。
2. 用户可查看 queued、running、waiting_confirmation、ready、failed 和 cancelled。
3. 失败状态显示数据是否保存、可否重试和下一步。
4. 重试从最近成功检查点继续，不重复调用模型、扣费或写正式数据。

验收：

- AC-JOB-001-01：Worker 中断、重复投递和数据库短暂故障后可恢复。
- AC-JOB-001-02：取消后不再产生新的正式副作用。
- AC-JOB-001-03：输入快照变化创建新任务，不复用旧候选。

### WORKBENCH-001 学习工作台

- 优先级：P0
- 状态：本地已验收

需求：

1. 注册后直接展示工作台。
2. 工作台展示待确认、今日复习、处理中任务、近期错题和推荐缺口。
3. 第一主操作始终指向当前最需要的下一步。
4. 所有卡片支持空、加载、失败和无权限状态。

验收：

- AC-WORKBENCH-001-01：新账号直接看到空错题本和“录入第一道错题”。
- AC-WORKBENCH-001-02：刷新后任务和草稿从服务端恢复。
- AC-WORKBENCH-001-03：键盘、焦点、对比度和表单错误达到无障碍目标。

### PRIV-001 敏感数据保护

- 优先级：P0
- 状态：本地已验收；生产复核待完成

需求：

1. 页面、日志、审计和错误默认显示脱敏手机号。
2. 验证码、密码、下载 token 和密钥不得明文持久化或进入普通日志；密码只保存经安全批准的自适应哈希、独立盐和参数。
3. 模型输入必须先通过 user_id 授权和必要性检查。
4. 原图、导出包和 PDF 使用短时访问授权。
5. 系统不采集身份证、人脸、法定身份或年龄信息。

验收：

- AC-PRIV-001-01：敏感数据扫描覆盖 API、任务、运营查询和异常日志。
- AC-PRIV-001-02：其他普通用户无法读取当前用户数据。
- AC-PRIV-001-03：模型候选包不含手机号、验证码、密码、密钥或不必要身份信息。
- AC-PRIV-001-04：数据字典和界面不存在必填实名、身份证、人脸或年龄字段。

### PRIV-002 个人数据导出

- 优先级：P0
- 状态：本地已验收；生产备份/恢复待完成

需求：

1. 当前用户二次验证后可申请导出自己的数据。
2. 当前本地导出为业务 JSON 和文件元数据，异步生成、短时下载，不包含上传原始二进制、其他用户数据或内部安全字段。
3. 下载最多 3 次，每次访问审计；未来完整可携带包需另行定义 ZIP/manifest 和原始文件策略。
4. 任务失败可安全重试，下载时再次检查会话。

验收：

- AC-PRIV-002-01：跨用户导出和对象链接访问全部拒绝。
- AC-PRIV-002-02：下载过期、次数限制和每次访问审计有效。
- AC-PRIV-002-03：失败重试不扩大范围或重复通知。

### PRIV-003 账号注销

- 优先级：P0
- 状态：本地已验收；生产恢复演练待完成

需求：

1. 当前用户二次验证后可申请注销并查看影响范围。
2. 注销执行时撤销全部会话并取消不应继续的任务。
3. 注销包含账号停用、业务逻辑失效和对象文件删除；认证、协议、审计等记录按数据分类策略匿名化或受控留存，不承诺无条件彻底删除所有数据。

验收：

- AC-PRIV-003-01：未通过二次验证的请求被阻止。
- AC-PRIV-003-02：注销后的登录、任务恢复和文件下载均失败。
- AC-PRIV-003-03：数据处置按类别可证明。

### OPS-001 运营与人工复核

- 优先级：P0
- 状态：待开发

需求：

1. 提供风控、短信预算、失败任务、内容质量和数据权利工单视图。
2. 运营默认只见脱敏信息；敏感访问需要审批、理由和审计。
3. 人工复核不能绕过 user_id、输入版本、来源授权和幂等质量门。
4. 危险批量操作需要预览、复核和回滚。

验收：

- AC-OPS-001-01：运营不能直接修改验证码、会话或正式判题。
- AC-OPS-001-02：复核结果保留操作者、证据、版本和时间。
- AC-OPS-001-03：高风险操作满足双人原则。

## 7. 通用任务状态

| 状态 | 用户含义 | 可用操作 |
|---|---|---|
| queued | 已收到，等待处理 | 查看、取消 |
| running | 正在处理 | 查看当前步骤 |
| waiting_confirmation | 需要确认识别或结论 | 修正、确认 |
| ready | 结果可用 | 查看、下载或继续 |
| failed_retryable | 暂时失败 | 从检查点重试 |
| failed_final | 无法自动完成 | 手工录入、客服或放弃 |
| cancelled | 已取消 | 查看保留内容、重新开始 |
| expired | 临时结果或链接过期 | 重新验证并生成 |

错误文案必须说明发生了什么、数据是否保存和下一步，且不得暴露堆栈、供应商正文或内部权限细节。账号存在性只允许通过认证场景规定的 `phone_not_registered` 和 `phone_already_registered` 两种最小反馈表达，不得泄露锁定、注销、最近活动或学习数据。

一级导航：

1. 工作台
2. 录入错题
3. 错题本
4. 今日复习
5. 练习与 PDF

## 9. 产品指标

| 指标 | 定义 | MVP 观察目标 |
|---|---|---|
| 注册直达率 | 注册事务成功后自动登录并加载工作台的占比 | 100%，不得被资料流程阻塞 |
| 首题闭环完成率 | 开始上传后得到正式错题和下一步的占比 | 验收样本不低于 90% |
| 待确认解决率 | waiting_confirmation 在 24 小时内完成处理的占比 | 不低于 80% |
| 今日复习完成率 | 到期任务中当天完成的占比 | 建立个人基线 |
| 推荐缺口率 | 需要推荐但无合格题的请求占比 | 真实记录，不用低质量题降低 |
| 人工复核率 | 正式判题中需要人工处理的占比 | 用于质量规划，不以越低越好 |

服务体验目标：

- 常规页面查询 P95 不高于 500 ms。
- 不含外部供应商的同步写操作 P95 不高于 1 秒。
- 异步任务在 2 秒内返回已受理状态。
- 生产关键路径月度可用性目标为 99.9%。
- 支持 Chrome、Edge、Safari 最近两个大版本，移动端宽度 360 px 起可用。
- 核心流程以 WCAG 2.2 AA 为无障碍目标。

## 10. 产品事件与隐私

允许事件：注册直达、上传开始/成功/失败、等待确认、正式错题创建、复习开始/完成、PDF 生成和导出/注销状态变化。

事件只使用内部 user_id 伪标识、任务类型、状态、耗时和错误分类；禁止写入手机号、验证码、密码、挑战令牌、题目正文、原图地址、下载 token 或模型完整正文。

## 13. MVP 上线门禁

> 当前状态：localhost + MySQL 8 的完整手工学习闭环已验收，134 项测试、真实 MySQL smoke、独立安全复核和浏览器注册/移动视口检查通过。以下门禁仍决定能否进入生产，不因本地通过而自动放行。

1. 所有 P0 活跃需求具有实现和可复现验收证据。
2. 新用户完成手机号、验证码、密码和协议注册后自动登录，可直接进入工作台并上传，不经过身份、家庭、档案或监护流程。
3. 至少完成一次从注册、上传、确认、判题、推荐、复习到 PDF 的生产等价端到端演练。
4. 验证码攻击、跨用户访问、恶意文件、重复任务、模型失败、导出越权和注销残留测试通过。
5. 未验证题、来源不允许题和低置信度候选无法进入推荐或正式题库。
6. 原始证据、候选、用户修订和正式记录可追溯。
7. API、后台任务、对象键、导出和运营后台均以服务端 user_id 隔离。
8. 本地全链路、安全复核和恢复演练通过后，才能由用户人工批准云部署。
