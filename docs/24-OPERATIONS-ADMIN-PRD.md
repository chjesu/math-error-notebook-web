## 1. 目标

运营后台用于发现和定位服务问题，不代替普通用户产品，也不建立第二套题库维护系统。首版只提供脱敏、只读的运营视图：

1. 账号、任务、内容质量、短信风险和隐私工单概览；
2. 失败或等待处理的任务列表；
3. 候选题与待复核验证记录；
4. 短信发送、失败和限流聚合；
5. 注销工单状态；
6. 后台访问审计。
7. 脱敏用户列表、账号状态和学习汇总；
8. 最近 7 天注册、上传、判题、入本、复习和 PDF 业务行为；
9. 按用户汇总的 Harness 供应商实报 Token 用量。

人工复核提交、敏感正文临时访问和危险批量操作继续后置，直到冻结审核包、审批、双人原则和回滚契约完成。

## 2. 入口与身份

- 后台使用独立入口 `/admin`，不出现在学生侧导航中。
- 操作者仍使用现有手机号验证码登录状态；后台不得建立平行登录状态机。
- `admin_operators` 只保存内部 `user_id`、后台角色和启停状态，不复制手机号或用户资料。
- 未登录返回 `401`，已登录但不是后台操作者返回 `403`。
- 本地环境可以按唯一手机号后四位显式授予角色；生产必须由受控运维流程完成。

| operations | 是 | 是 | 是 | 是 | 是 | 否 | 是 | 否 | 否 |
| reviewer | 是 | 否 | 否 | 否 | 是 | 是 | 否 | 否 | 否 |

| administrator | 是 | 是 | 是 | 是 | 是 | 是 | 是 | 是 | 是 |

每次读取后台数据都记录操作者、角色、读取区段和时间。普通页面和普通日志不提供手机号状态检索。

## 4. 数据展示规则

- 用户只显示“用户 ····后四位”，不返回手机号、手机号哈希或密文。
- 任务显示内部任务 ID、类型、状态、错误分类和时间；默认不显示题目正文、答案、文件路径和模型提示。
- 内容质量显示题目 ID、候选/验证状态、版本、授权状态和时间；默认不显示题目正文与原图。
- 短信只显示数量和状态聚合，不提供按手机号搜索。
- 隐私工单显示脱敏用户、处理状态、错误分类和时间，不返回导出内容。
- 后台页面不提供直接修改验证码、会话、正式判题、错题、题库验证状态或用户数据的按钮。
- 用户行为只统计现有权威业务记录，不植入页面点击追踪；“活跃”表示当天发生注册、上传、判题、入本、复习或 PDF 事件。
- Token 采用 Harness `token-meter` 的供应商实报累计值，服务端只接受当前登录账号已经绑定的会话，重复上报按会话总量覆盖且不得倒退。
- Token 首版展示数量，不在未配置正式模型单价时估算金额。

## 5. 页面标准

页面沿用 Harness 产品的字体、中性色、间距、圆角、按钮和状态表达，但使用独立后台导航：

- 顶部显示“运营后台”、当前角色和返回用户端入口；
- 首屏用少量指标卡回答“当前是否需要处理”；
- 任务、内容、风险、隐私和审计分别使用可折叠区段；
- 用户、行为和 Token 各自使用独立区段；用户列表只显示手机号后四位；
- 空状态说明“当前没有待处理项”，不显示空白表格；
- 表格在窄屏下改为卡片，不产生横向页面滚动；
- 状态不仅依赖颜色，同时提供中文文本；
- 刷新失败保留上一次结果并给出明确错误提示。

## 6. 本地候选验收

- 普通账号无法访问后台页面和接口；
- 各角色只能看到权限表允许的区段；
- 响应中不出现手机号、手机号哈希、题目正文、答案、文件路径或模型提示；
- 后台读取产生不可由页面修改的审计事件；
- 后台没有业务写操作；
- 一个 Harness 会话不能重新绑定给另一个账号，Token 上报不能冒用未绑定会话；
- 桌面与移动视口均可使用键盘完成刷新和区段导航；
- 完整自动化测试通过。

## 7. 生产前仍需完成

- 敏感访问审批、理由、有效期和自动撤权；
- 冻结人工复核包和带版本门的复核提交；
- 双人批准、批量预览、执行回执和回滚；
- 生产日志、指标、告警、成本数据和不可变审计存储；
- 独立安全复核、权限回归和灾备演练。
