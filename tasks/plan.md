# Phase 2：异步摄取与判题任务管线

## 目标

把图片摄取、拆题、判题改成可恢复的后台批次；创建接口立即返回 `202`，浏览器通过可重放 SSE 显示进度，刷新后从最后事件继续。

## 冻结边界

- `intake_batches` 是批次状态的唯一事实源；用户、输入文件顺序、当前阶段、进度、租约和终态均由服务端持久化。
- 状态只允许 `pending -> slicing -> solving -> grading -> completed`，任一非终态可进入不可变终态 `failed`；每条边都要求当前 fencing token、租约和预期源状态匹配，其他转换一律拒绝。
- 每次状态变化和对应 `intake_batch_events` 在同一事务提交；事件序号在单批次内严格递增。
- `POST /v1/intake/batches` 仅接收当前会话用户拥有且可用的图片文件，使用 `Idempotency-Key`，返回 `202`、批次快照和事件地址。精确幂等重放优先返回原结果；新请求每账号最多保留 3 个非终态批次、滚动 24 小时最多创建 60 个，超限稳定返回 `batch_limit_reached` / `batch_rate_limited`。
- `GET /v1/intake/batches/{batch_id}` 和 `/events` 始终按当前会话用户过滤；不存在和越权统一返回 `404`。
- SSE 使用批次内十进制序号 `Last-Event-ID` 重放，完整事件保留到批次删除；缺失等同 0，格式错误或未来序号返回 `invalid_event_cursor`。每次连接重新认证和鉴权；慢客户端断开但不丢持久事件，终态发出后关闭。单进程最多 200 条 SSE、每账号 4 条、每批次 2 条；服务端监听 `http.disconnect` 即时释放计数，空闲时最多每秒查询一次。批次事件只含阶段、计数和稳定错误码；仅所有者可见的 `item_completed` 额外包含最多 2,000 字的题目/作答快照、判定和入本状态，不含内部 ID、图片、模型提示或账号信息。
- GET 和 SSE 共用快照字段：固定 `total_files`、切题完成后冻结的 `total_items`、单调递增的 `completed_files/completed_items`、`status/current_stage/terminal/last_event_id/error_code`；GET 必须与最新事件一致。
- 部署范围内只有两个数据库工作槽位。领取批次与槽位在同一事务完成，并递增 `claim_epoch` 形成 fencing token；所有进度、结果、事件和续租写入都必须同时匹配槽位、token、未过期租约和预期状态，过期工作者写入无效。数据库时间是唯一租约时钟。模型调用在事务外执行；每个幂等领域写入事务在首尾都依次锁定并复核槽位、批次、阶段、账号删除门和数据库租约，提交前再次续租。操作回执在独立批次事务提交，因此进程若在领域提交后、回执提交前崩溃，恢复流程以稳定操作键和领域唯一约束对账后补写回执，不重复入本。
- 调度器持续扫描所有到期非终态批次，不只在启动时恢复。租约 5 分钟、每阶段提交前续租；单阶段最多 3 次，按 5/10 秒退避，耗尽后原子进入 `failed`。模型调用可能因超时重算，但只有带有效 fencing token 的一次事务可提交结果。
- 阶段尝试次数在每次领取时原子增加；领取后进程崩溃也消耗该次尝试。租约到期后可领取下一次；若已记录 3 次尝试，下一次扫描不再领取，而是原子写 `failed/retry_exhausted` 和唯一终态事件。
- 幂等键按“用户 + 创建批次操作”永久保留，和规范化请求指纹、批次及初始响应原子持久化；并发重复返回同一响应，不同指纹复用返回 `idempotency_conflict`。
- 创建时按顺序快照文件 ID、对象键、媒体类型、字节数和 SHA-256；批次终态前不得替换或重排，工作者只消费快照并重新校验完整性，缺失时使用稳定错误码 `input_unavailable`。
- 模型输出仍是不可信候选；确定性代码负责输入校验、状态推进、确认和写入。失败闭合为 `failed`，只记录稳定错误码。
- 账号注销先与批次创建共用账号行锁，持久写入删除门；精确幂等重放仍可查询，但任何新批次都被拒绝。随后取消流程按领取一致的全局顺序锁两个固定槽位和用户非终态批次，精确匹配当前 `slot_id + batch_id + claim_epoch + lease_owner` 释放槽位，并在同一事务写 `failed/account_deleted` 和唯一终态事件。它不要求租约仍有效，以免注销等待失联工作者；领域写入事务也会复核删除门。
- 页面发现接口首先返回服务端生成的毫秒游标和当前活动批次；客户端后续只回传这个服务端游标。若已无活动批次，则返回游标之后刚更新的最新终态批次，避免客户端时钟偏差和批次在两次轮询间完成导致漏接 SSE。客户端按批次 ID 和事件 ID 去重。
- 模型返回的 `cross_validation` 一律丢弃。服务端用 solving 阶段冻结的独立答案与当前已验证题库确定性重算；解题回执只保留有长度、数量和总 JSON 上限的白名单字段。判题候选绑定 `batch_id + grade:ordinal + solve_sha256`，崩溃恢复只采用本批次精确身份的候选。关联题库、自动入本或因冲突抑制入本前，领域事务再次锁定并核对题库 ID、版本、匹配分数和答案哈希，变化时安全失败。

### 规范转换表

| 源 | 目标 | 执行者与前置条件 | 事件与进度 | 重试/终态 |
|---|---|---|---|---|
| `pending` | `slicing` | 调度器已原子取得槽位、有效 token 和租约 | `progress`；计数不变 | 可在原状态有限重试 |
| `slicing` | `solving` | 工作者提交全部文件的拆题结果，token/租约/源状态匹配 | `progress`；`completed_files=total_files`，冻结 `total_items` | 可在 `slicing` 有限重试 |
| `solving` | `grading` | 每个题目的独立解答均以稳定操作 ID 条件提交 | `progress`；阶段计数达到 `total_items` | 可在 `solving` 有限重试 |
| `grading` | `completed` | 每个题目的判定及允许的错题写入均幂等提交 | 逐题 `item_completed`，最后 `batch_completed`；`completed_items=total_items`，释放槽位 | 不可变终态 |
| 任一非终态 | `failed` | 不可重试错误或同阶段第 3 次失败，token/租约/源状态匹配 | 唯一 `batch_failed`，稳定 `error_code`，释放槽位 | 不可变终态；重新创建新批次 |

同一状态内的文件/题目进度用 `progress` 或 `item_completed` 事件更新；每个操作 ID 为 `batch_id + stage + file/item ordinal`。模型调用允许因超时或崩溃重复计费，因为 Provider 没有冻结的幂等契约；领域写入只在有效租约的行锁保护下执行，并依靠稳定业务键在“领域已提交、回执未提交”的恢复窗口去重。
