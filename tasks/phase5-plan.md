# Phase 5：学习画像与递进练习

## 目标

在不改变错题、诊断和题库事实归属的前提下，把已有标准错因转化为可筛选的错题列表、用户学习画像、同类递进推荐，以及“复习卷 / 自测卷”两种 PDF。

## 任务路由

- `design_gate`：T1（事实归属、公共 API、MySQL 迁移、兼容和失败语义）
- `implementation_tier`：T2
- `implementation_model`：当前 Codex 主会话；运行环境未向任务卡暴露精确型号和 effort
- `final_review`：`gpt-5.6-sol` / `high` / fresh context
- `escalation_reason`：无；按默认 T1 最终门禁执行

## 冻结契约

- `grade_candidates.evidence_text` 中已校验的诊断 JSON 是错因和知识点的事实源；错因属于学生本次作答形成的错题，不写回题目。
- 错因固定使用现有 12 个 `cause_code`；请求边界只接受白名单值，所有查询继续按当前会话 `user_id` 隔离。
- MySQL 8 只读视图展开错因与知识点，视图用于统计和过滤，不代替应用层权限检查。
- 推荐先按原题文本上下文匹配，再相对原题难度向上递进；当前错因只作为本次训练目标，不成为候选题的永久标签。
- PDF 模式固定为 `review` 与 `self_test`：复习卷包含错因、知识点、解析和答案；自测卷只包含题目和作答留白。
- HTTP 暂时兼容旧 `include_answers` 字段；新请求和内部状态统一使用 `mode`，冲突输入失败关闭。

## 增量

1. 增加学习事实视图和聚合领域函数。
2. 增加错因筛选与学习画像 API。
3. 扩展推荐排序和解释文本。
4. 重构 PDF 为复习卷与自测卷两种模板。
5. 在错题、进度和练习页面增加对应入口。
6. 更新 OpenAPI、架构和阶段状态。

## 验证

- 聚焦运行学习领域、PDF、MySQL 查询、ASGI 契约、OpenAPI 和前端静态测试。
- 对变更 Python 文件做 AST 语法解析，对 JavaScript 做语法检查。
- 检查补丁空白、用户归属、白名单输入、参数化查询和模式兼容。
- 不运行全量测试，遵循用户本阶段指示。
